# AI-Harness 재검토와 적용 기록

## 기준과 범위

- 2026-11-11 기준 원본 `main` 커밋 `f8ad6d70c035d8cd8606b1aae66767b169baebac`. 이전 98파일 검토와 별도의 현행 스냅샷이다.
- 원본 트리의 파일 213개를 모두 읽어 목록·역할·라이선스 단서를 분류했다. 구성은 스킬 자산 57개, 문서 45개, 스크립트 21개, 테스트 51개, 나머지 설정·런타임·안내 39개다. 자동 분류와 관련 기능의 상세 대조이며 모든 코드 경로의 실행 검증이나 보안 감사를 뜻하지 않는다.
- 대상은 이 저장소의 9개 스킬, Claude Code·Codex·Grok Build 설치 및 평가 하네스다. 원본의 지침은 참고 자료이며 현재 사용자·호스트 지침을 대체하지 않는다.

## 라이선스와 자료 경계

- 두 저장소의 루트 라이선스는 Apache-2.0이다. 원본의 `design-evidence-harness` 하위 폴더에는 별도의 MIT 고지가 있고, 일부 문서는 제3자 스킬이나 라이선스 미확인 자료를 논한다. 루트 표시만으로 그 자산의 권리가 모두 해결됐다고 보지 않는다.
- 원본 코드·문장·프롬프트·자산은 복제하지 않았다. 쌍별 집계와 CLI 사용량 분리의 요구사항을 현재 저장소 형식에 맞게 독립적으로 작성했다. 사용자의 실제 데이터, 외부 모델 응답과 추적 원문은 저장소에 넣지 않았다.
- 새 집계 스크립트와 테스트, 기존 파일에 추가한 관련 코드·지침의 각 40자 창을 원본 213개 파일과 대조했다. 공백을 제외한 길이가 20자 미만인 창을 제외하면 신규 스크립트와 테스트는 일치 0건이며, 기존 파일의 추가분에서는 일반적인 Python 테스트 구문에 걸친 창 3건이 일치한다. 이는 해당 스냅샷에 대한 기계적 비교이며 원본이 참조한 모든 제3자 자료와의 유사성이나 법적 판단을 보증하지 않는다.

## 검증 한계

집계는 사용자가 제공한 판정과 비교 조건의 일관성만 확인한다. 실제 평가 실행, 독립 판정, 사전 계획의 진위, 통계적 유의성 또는 품질 향상을 입증하지 않는다. 스킬 선택·파일 표시·수식·접근성·플랫폼별 모델 동작은 각각 별도 증거가 필요하다. 실제 실행 및 미검증 항목은 `docs/VERIFICATION.md`에 기록한다.

## 후속 보강 (1.16.0)

사용자 요청에 따라 일반 시각 디자인 스킬, 자연스러운 문체 편집 기준, 디자인·글쓰기 비교 절차와 평가 사례를 추가했다. 기존 검토의 출처·권리 경계를 유지하고 지침은 이 저장소의 요구에 맞춰 새로 작성했다. 위의 40자 비교는 1.15.0 당시 범위이며 후속 보강 파일에는 적용한 결과가 아니다. 원본 자산 사용 허락이나 법적 적합성을 보증하지 않는다.

### 문서 작성 자산 대조

원본 `document-master`, `writer-master`, `office-master`, `ppt-master`, `ppt-master-style` 및 관련 검토·형식 지침, 문서 작업 계약을 다시 확인했다. 이전에는 그 문서 작성 스킬의 일부 원칙만 반영했다. 이번에는 아래 범위를 이 저장소의 지침으로 새로 구성했다.

새 문서 스킬 두 파일과 Office 지침·평가 사례의 추가 부분을 위 문서 관련 원본 14개 파일과 40자 창으로 비교했다. 공백을 제외한 길이가 20자 미만인 창을 제외하고 일치 0건이다. 전체 원본이나 제3자 저작물과의 법적 유사성을 보증하는 검사는 아니다.

| 원본의 관심사 | 반영 위치와 범위 |
| --- | --- |
| 독자·목적, 문서 유형, 근거와 처음 읽는 사람의 확인 | `document-authoring`: 작업·학습·참조·설명에 맞춘 구성, 주장과 근거 연결, 자체 독자 관점 점검 |
| 편집·출처·불확실성 | `writing`의 편집 강도·자연스러운 문체·사실 경계, `document-authoring`의 근거 구분 |
| 발표자료의 이야기와 차트 | `office-docs`의 슬라이드 제목 연결, 값·축·단위·범례와 주장의 일치, 편집성과 렌더 검증 |
| 형식별 결과물과 검증 | `office-docs`의 PPTX·DOCX·XLSX·PDF 지침과 입력별 완료·실패, 실행하지 못한 검사 기록 |
| 다중 문서 작업 계약 | 입력별 결과 대응과 미실행 기록을 지침에 반영. 별도 원격 번역 실행기·원본 JSON 계약은 도입하지 않았으며 실제 번역·배치 처리 기능을 제공한다고 주장하지 않음 |

원본의 모든 슬라이드에 결론형 제목, 고정된 3장 샘플, 모든 작업의 승인 중단, 정해진 보고 블록과 독립 평가 의무는 그대로 적용하지 않는다. 표지·소규모 수정·사용자의 즉시 완성 요청에 맞지 않거나 이 저장소에서 검증하지 못한 절차이기 때문이다. 실제 독립 검토나 렌더링 여부는 각각 보고한다.
