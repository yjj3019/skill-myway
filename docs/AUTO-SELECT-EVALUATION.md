# 스킬 자동 선택 평가 설계 (draft)

현재 `scripts/run_eval.py`는 케이스마다 `case["skill"]`을 프롬프트에 명시한다. 즉 **스킬 지정 후 출력 검사**는 가능하지만, 일반 사용자의 자연어 요청만으로 올바른 스킬·조합이 선택되는지는 검증하지 않는다. 이 문서는 그 공백을 메우는 자동 선택(auto-select) 평가 설계다.

> 상태: **설계 초안**. 스크립트·모델 실행·판정은 아직 없다. 실행하기 전에 4절의 오염 방지 규칙에 따라 케이스와 판정 기준을 고정한다.

## 1. 평가군 구성 (스킬명 미지정)

각 케이스는 `request`만 있고 `skill`을 지정하지 않는다. 정답은 가이드(평가자용)로 관리한다.

| id | 사용자 요청 (자연어) | 정답 스킬/조합 | 확인할 점 |
|---|---|---|---|
| as-01 | 고객에게 RHEL 점검 결과를 보고할 엑셀을 만들어줘 | office-docs (+필요 시 writing) | 산출물 형식·독자 맞춤, 다른 스킬 불필요 |
| as-02 | 이 CVE를 조사해서 고객 보고서로 만들어줘 | rhel-cve → office-docs | 조사 후 문서 변환 흐름, 형식 준수 |
| as-03 | 이 장애를 분석하고 경영진 보고 자료를 만들어줘 | incident-rca → office-docs | 원인 분석 후 발표자료 변환 |
| as-04 | 최신 AI 소식을 조사해서 내 블로그 스타일로 써줘 | research-brief → writing | 조사 + 개인 문체 적용 |
| as-05 | 이 문서에 있는 개인정보가 없는지 점검해줘 | writing (민감정보 점검) | 스킬 호출 불필요 시 "일반 응답"도 허용 |
| as-06 | 방금 만든 리포트의 근거를 다시 검토해줘 | evidence-first | 근거 재검토만, 새 스킬 불필요 |
| as-07 | 다음 실행 계획을 프롬프트 설계 규칙으로 검토해줘 | prompt-engineering | 설계 규칙 참조 |
| as-08 | 이 코드 변경의 문제를 찾아줘 | code-review | 리뷰 범위 한정 |
| as-09 | 운영 가이드 문단을 다듬어줘 | writing | 교정·편집 모드 |
| as-10 | RHEL 8 영향 있는지 확인만 해줘 | rhel-cve (검증 답변 모드, 파일 없음) | 질문 모드 → 파일 생성 금지 |

**부정 사례**: as-05·as-06처럼 스킬이 없어도 되는 요청에서 불필요한 파일을 만들지 않는지, as-10에서 리포트 대신 대화 응답인지 확인한다.

**도구 없는 환경**: 파일 생성 스킬(as-01~04)이 도구 없이 계획만 내놓는 대체 경로를 쓰는지, 대신 만들지 않는지 본다.

## 2. 판정 기준

- **선택 정확성**: 정답 스킬/조합이 호출됐는지, 불필요한 스킬을 호출했는지.
- **조합 순서**: 조사(rhel-cve·research-brief·incident-rca) → 생성(office-docs·writing) 순으로 수행되는지.
- **하드 실패**: EVALUATION.md 기준(민감정보 노출, 검증 통과 위조, 형식 무시, 지시 주입 실행)을 그대로 적용.
- **환경 기록**: 모델·도구·스킬 본문·요청 해시·실행 시각·실패/미실행 분모.

## 3. 실행기 확장 방향

```text
run_eval.py --auto-select      # skill 미지정 케이스군 실행, 선택 결과를 'selected: [..]'로 기록
run_eval.py --expected as-04   # 정답 기대(스킬명)를 stdout 검사와 별도로 분리 보관
```

- 자동 선택 결과는 `case["skill"]`을 프롬프트에 넣지 않는다.
- 선택된 스킬 목록·파일 생성 여부·경로는 출력에서 수집해 사람이 가이드와 대조한다.
- 실제 모델 실행은 이 문서만으로 하지 않는다. 실행 전 권한·격리·예산을 재확인한다(EVALUATION.md 개선 실험 운영).

## 4. 오염 방지와 보관

- 케이스 요청과 판정 가이드(정답)는 **같은 저장소에 분리 파일로 두지 않는다**. 이 문서의 표는 설계용이며, 실행 전 정답 가이드는 저장소 밖(로컬)에 보관해 모델 프롬프트·스킬 지침에 노출되지 않게 한다.
- 공개 케이스는 개발·회귀용으로만 쓰고, 최종 확인은 미노출 사례로 한다.
- 사례별 "실행 여부·실패·미실행 수"와 환경을 기록해야 VERIFIED로 표시할 수 있다. 그 전까지 이 설계의 수행 결과는 NOT VERIFIED다.

## 5. 이 문서의 검증 기준

- 자동 선택 케이스 10건 + 부정 사례가 `tests/eval_cases/`와 분리된 설계로 유지되는지 구조 검사.
- 실행기 확장 후 `--auto-select`가 스킬명을 삽입하지 않는지 부정 테스트.
- 실제 모델 실행 결과는 VERIFICATION.md 현재 상태 표에 반영하기 전까지 NOT VERIFIED.
