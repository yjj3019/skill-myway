# 실측 반례 보강 계약

기준: `docs/ALL-SKILL-CRITICAL-EVALUATION.md`에서 관찰된 개발용 반례. 각 항목의 해법은 원문 복사 없이 현재 스킬에 맞춰 작성한다. 보강 전과 후의 같은 사례·조건 쌍별 평가가 아니므로 실제 성능 향상을 사전에 주장하지 않는다.

시간 구간·취약점 조치·화자의 기대·장별 가상 수치·원문 미확인 확신도·교육용 공격 인용·코드 구문 불확실성의 7개 공개 개발용 사례를 `tests/eval_cases/critical-cases-extra.json`에 기록했다. 11개 스킬 커버리지가 필요한 실행기는 이를 기존 44건과 결합한 `tests/eval_cases/critical-regression-cases.json`을 사용한다. 의미 판정은 `tests/eval_cases/critical-review-rubric.md`를 적용한다. 단어 존재 검사는 인용·부정의 의미를 판정하지 않는다.

실측 재확인은 보강된 본문을 직접 넣은 Claude 공개 개발 사례 7회로 제한한다. reference 로드나 자동 선택, 독립 평가, 미노출 사례 및 디자인 렌더는 이 실험으로 확인하지 않는다. 코드·파일 생성은 요구하지 않으며 실패·미실행·사용량 제한을 성공으로 바꾸지 않는다.

추가로 최종 지침에 대해 Codex에서도 같은 7개 공개 사례를 한 번씩 실행한다(최대 7회). 한 모델의 응답으로 다른 플랫폼의 동작을 추정하지 않는다. 결과와 미실행은 따로 기록한다.

## 실제 변경

`incident-rca`, `rhel-cve`, `writing`, `office-docs`, `research-brief`, `code-review`의 본문에 각각 위 조건을 추가했다. 7개 주제는 research-brief의 원문 확신도와 교육용 인용이 별도이므로 6개 스킬에 대응한다. 패키지 버전과 5개 매니페스트를 1.16.5로 맞췄다. 외부 코드·소재·의존성은 들여오지 않았고 기존 라이선스와 선행 권리 미확인 범위는 유지한다.

## 실제 재확인 및 추가 결함

- Claude 공개 개발 사례 7회가 모두 응답했다. 자체 의미 대조에서 제품 조치, 화자 기대, 장별 20%, 원문 신뢰도, 교육용 인용, 구문 불확실성 6개는 해당 사례의 수동 기준에 맞았다. 발표자료 계획의 끝에 사용자가 요청하지 않은 추후 파일 생성을 예고한 문구가 남았으며, 이는 결과의 범위 관리에서 주의할 점이다.
- 장애 시간 첫 응답은 완화까지 35분을 총 시간의 상한으로 쓰지 않았지만, 연속 영향 여부가 불명확한데 `최소 35분`이라고 단정했다. **실패 반례**로 기록하고 지속 구간과 누적 영향의 하한 조건을 본문·루브릭에 추가했다.
- 두 번째 응답은 누적 영향의 하한을 단정하지 않고, 완전 복구가 완화보다 빠르지 않다는 전제를 붙여 총 구간의 조건부 하한을 설명했다. 이후 총 구간 하한의 전제도 지침에 명시하고 세 번째로 재호출했다. 세 번째 응답은 전체 지속 시간과 누적 영향 시간의 하한을 단정하지 않았으나, 같은 날짜·시간대라는 전제를 설명하면서 표제에 `확정`이라는 표현을 사용했고 끝에 불필요한 영문 표식이 남았다. 이를 근거로 조건부 계산을 제목에도 명시하도록 본문을 마지막으로 보강했다. 마지막 보강 후 실모델 재호출은 하지 않아 효과는 미검증이고 영문 표식도 해결됐다고 주장하지 않는다.
- Codex에서도 당시 지침을 직접 전달한 동일한 공개 개발 사례 7건이 모두 응답했고, 자체 검토에서 이 사례들의 수동 기준을 충족했다. 위 마지막 제목 조건 보강은 그 호출 이후에 추가됐다. 단회 결과로 다른 입력이나 자동 스킬 로드의 품질을 보장하지 않는다.
- 실제 재호출은 Claude 9회·Codex 7회, 총 16회다. 모든 출력은 `eval-results/critical-recheck-20261114/`에 보존한다. 첫 7개, 시간 사례 v2와 최종 v3, Codex 7개를 구분한다. Grok의 변경 후 실제 평가, 미노출 사례, 독립 검토와 기준본·후보의 통제된 쌍별 비교는 NOT VERIFIED다.

## 검증 범위

현재 7개 추가 사례와 기존 44개를 합친 51건·11개 스킬의 스키마·커버리지 검사 및 수정된 6개 스킬의 형식 검증을 수행했다. 실제 결과 검토는 작성자의 수동 검토다. 수동 기준을 응답을 본 뒤 조정했으므로 이 결과를 독립 최종 평가나 일반적인 성능 향상으로 간주하지 않는다.

모델과 병렬로 실행한 전체 테스트는 Windows 프로세스 시작 지연과 관련된 실패 1·오류 2가 발생했다. 이후 단독 실행은 242건 통과했으나 실행 중 스킬 문구가 바뀌었으므로, 최종 문구 변경 후 다시 단독 실행했다. 마지막 실행은 242건·실패 0·skip 0이었다. 부하와 실패의 인과관계는 미확인이다.
