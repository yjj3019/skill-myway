# 설계 결정

- 평가 요약의 `original_command`는 원래 실행 인자, `rerun_command`는 작성 시점에 비어 있는 새 출력 경로의 명령이다. Markdown은 Windows PowerShell 또는 POSIX 셸에서 인자 경계를 보존하도록 표기한다.
- 설치 진단은 직접 설치 대상의 스킬별 본문 존재 여부를 검사한다. 블라인드 패킷과 키는 독점 게시하고 중간 실패 시 공유 이름을 삭제하지 않는다. ZIP 일괄 생성은 이름 충돌을 먼저 검사하고 중간 실패 시 진행 목록을 보고한다.

- 기준선과 후보의 자동 상태 차이는 검증한 상태 건수·통과 수·통과율 및 실행기의 `auto_checks_passed` 판정으로 계산한다. 비교 보고서의 `passed_count`와 `auto_passed`는 같은 검증값을 사용하며, 입력 진단은 `input_issues`에 기록한다.

## 2026-11-23 대조 보고 동시성·집계 정정

- 공유 경로에서 파일 내용 또는 식별자 확인 후 삭제하는 방식은 확인과 삭제 사이 교체를 막지 못한다. 중간 게시 실패 시 최종 경로를 자동 삭제하지 않고 부분 저장 가능성을 알리며 빈 출력 디렉터리로 재시도한다. 안전한 삭제를 우선한 선택으로, 기존의 자동 롤백과 자동 재시도 가능성은 제공하지 않는다. 두 파일의 쌍 원자성, 비협조적 외부 변경과 강제 종료 후 일관성은 보장하지 않는다.

## D-021 실행 버전 호환과 플랫폼 갱신 동작 (1.5.0)
시뮬레이션·실환경 검증에서 확인한 동작을 고정한다.
- `scripts/run_tests.py`는 Python 3.11 이하에서 `__init__.py`가 없는 임시 디렉터리를 테스트 대상으로 넘기면 테스트 탐색이 실패한다. `discover()`에 `top_level_dir`을 시작 폴더로 고정해 해결하고, Python 3.11·3.13·3.14에서 51건 통과를 확인했다.
- Claude Code 갱신은 `claude plugin marketplace update` + `claude plugin update`로 동작한다(1.5.1 → 1.5.2 확인). Codex 로컬 경로 마켓플레이스는 `marketplace upgrade`가 git 전용이라 경로를 다시 추가한 뒤 `plugin add`로 재설치한다. Grok 로컬 마켓플레이스 등록 이름은 폴더명이므로 `grok plugin install myway`처럼 이름을 생략하고, 갱신은 `grok plugin update`를 쓴다.
- 검증기는 플러그인 source의 `..` 경로를 거부한다. 플랫폼 검증기(Claude·Codex·Grok)는 매니페스트 JSON 오류를 거부하지만 source 디렉터리 존재는 설치 시점에 확인하므로, 저장소 검증기의 경로 검사를 함께 쓴다.

- 근거: 승인 전에 전체 초안과 바이너리 파일을 중복 생성·출력하지 않아 토큰과 렌더링 비용을 줄인다. 미리보기는 요약만 남기며 HTML 자체가 Markdown보다 짧다고 가정하지 않는다.

## D-034 수식 계산·EVR 비교·검사 범위 증거 구분 (1.13.0)
- 2026-11-07 점검에서 XLSX 4상태 지침은 있으나 `check_office.py`는 수식 문자열만 확인함을 확인했다. 샘플 수식에 한해 LibreOffice/soffice 재계산, 수식 보존, 캐시, 명확한 기대값을 별도 확인하고, 엔진 부재·오류 시 NOT VERIFIED를 JSON에 보고하도록 변경했다. 구조 루틴 반환코드와 계산 상태를 분리한다. 반복·가상 수식 시뮬레이션과 단위 테스트로 확인한다.
- 자동 선택 평가가 Office 산출물을 생성해도 실제 파일 재열기·매크로·외부 관계 검사를 하지 않는 공백을 확인했다. Codex/Grok의 격리 작업 폴더에서만 `--inspect-artifacts`를 제공해 Office 구조, 압축 경로·크기, 매크로·외부 관계를 검사한다. XLSX 캐시 누락은 계산 `NOT VERIFIED`, 캐시된 계산 오류는 `FAIL`로 구조 상태와 분리한다. 검사를 통과한 구조도 렌더링·실제 Office 호환성을 입증하지 않는다.
- RHEL 문서의 epoch 제거 문구를 원본 EVR 보존, RPM 비교 완료 후 표시 변환으로 정정했다. formatter의 epoch 검사는 표시 형식 검사이며 EVR 비교를 증명하지 않는다.
- `RENDER-GATE.md`와 과거 Office 기록에서 구조·계산 검사와 실제 산출물 검증·렌더·시각 리뷰의 범위를 분리했다.
- 외부 자료의 주장별 근거표는 `research-brief`에 이미 있어 새 추적 체계는 추가하지 않았다. 오피스 접근성·입력 셀의 수식 주입과 외부 링크 점검 기준은 `office-work.md`·`pptx.md`에 보강했으며 자동 검사는 미구현이다.
- RHEL 스킬 명세를 Confluence Markdown 출력, 단건/통합 모드, HTTP 상태코드 처리, 통합 8컬럼, 보고서 제목·파일명 검사에 맞춰 개정했다. 신규 평가 사례는 가상 식별자를 사용한다. 기존 실사례 참조 하나는 가상 EVR 예시로 교체했고, 관련 평가 케이스도 예약 CVE 식별자로 바꿨다. 실제 외부 자료와 대조하는 평가는 승인된 별도 미노출 데이터가 필요하다.
- 1.14.2의 무라이선스 RHEL mirror 대조에서 긴 동일 블록을 확인했다. 기능을 삭제하지 않고 조사 설명·요약·판정 규칙·EPSS/KEV 처리·checker의 위험 문구를 요구사항 중심 새 구성으로 바꿨다. API/CSV 폴백과 실패 분류 fixture를 추가했다. 1.14.4는 원격 `ab5fcf2` 위 forward correction을 위한 로컬 검증 후보이며 force-push하지 않는다. 그 커밋 이력은 원격에 남으므로 과거 노출은 소급 제거되지 않는다. 사용자가 요청한 커밋/푸시 과정에서 이 한계를 숨기지 않는다.

## D-035 독립 스킬 패키지와 평가 증거 (1.15.0)
- 단일 ZIP에서는 다른 스킬의 reference와 저장소 docs를 사용할 수 없다. writing·incident-rca에 미리보기 지침 사본을 두고 테스트로 office-docs 원본과 일치시킨다. office-docs의 리뷰 계약은 독립 패키지 안에 두고 프로젝트별 기준은 제공된 경우 적용한다.
- 일반 평가에서 내용 조건 없는 답변을 자동 통과시키지 않는다. 문자열 확인과 사람의 의미 판정을 분리하고, Codex JSONL과 시간 초과 시 회수한 부분 산출물은 결과 폴더에 기록한다. 이 기록은 민감할 수 있으므로 외부 공개 전에 확인한다.
- Claude의 스킬 이름을 프롬프트에만 적으면 실제 `Skill` 호출 없이 답하는 사례를 관측했다. 지정 평가는 Claude의 스킬 도구 또는 Codex·Grok의 프로젝트 스킬 파일을 명시하고, Claude·Codex는 성공한 로드 이벤트와 현재 본문 일치로 실제 로드를 판정한다. 자동 선택 평가는 스킬명을 주지 않는다.
- Python 테스트 의존성을 명시하고 CI에 LibreOffice가 있는 별도 검증을 추가한다. CI 설정 추가는 실제 원격 실행 성공이나 전체 Office 호환성의 근거가 아니다.

## D-036 시각 디자인과 문체 검증 (1.16.0)

- 일반 화면·시각 자료를 위한 `visual-design`을 추가한다. Office 양식은 기존 `office-docs`가 담당하고 시각적 판단이 필요할 때 두 스킬을 조합한다.
- 자연스러운 문체는 특정 표현의 기계적 삭제나 탐지 회피가 아니라 독자 적합성과 의미 보존으로 판단한다. 새 지침의 실제 모델 효과는 별도 비교 전까지 미검증이다.
- 디자인과 문체 평가는 사례·기준·실행 환경을 기록하고 자동 검사와 사람의 의미·시각 판정을 분리한다. 공통 고정 점수나 미검증 화면의 통과 선언은 사용하지 않는다.
- 기술 문서·매뉴얼용 `document-authoring`을 별도 도입하고 기존 writing·office-docs와 독립 설치 가능하게 조합한다. 원본의 사용자 요청과 충돌하는 일률적 샘플·제목·승인 게이트는 적용하지 않는다.
- 개별 스킬 ZIP·복사 설치본에 적용 가능한 스킬별 LICENSE가 없으면 저장소 라이선스를 포함하고, 플러그인 디렉터리에도 동일한 라이선스 사본을 둔다. 과거 배포물과 권리 미확인 이력은 이 조치로 소급 정정되지 않는다.
- 사용자 요청에 따라 새 `document-authoring`, `visual-design` 스킬에는 MIT를 적용하고 그 외 기본 라이선스는 Apache-2.0으로 유지한다. 선행 권리나 공개된 과거 이력은 변경되지 않는다. 명시된 스킬 라이선스 파일이 없거나 MIT 저작권 표시·표준 본문이 검사 조건에 맞지 않으면 중단한다. 배포본에는 검사한 스킬 선언과 라이선스 바이트를 넣고, 직접 하위 스킬만 선택하며 원본 링크와 트리 밖 경로를 거부한다. 이는 전체 파일의 동시점 스냅샷, OS 보안 경계, 권리 보유나 모든 라이선스 표기 방식의 자동 판정이 아니다.

## D-037 RHEL 보고서 검사기 구조 재설계 (1.16.0)

- 단건·통합 Markdown의 제목, 순서, 필수 내용, 표 및 CVE 연결은 유지하면서 입력 정규화·형식별 규칙·표 검사로 분리했다. 단건 제목과 파일명 ID의 불일치는 새로 거부한다.
- 검사기는 구조만 확인하며 보안 사실·출처·RPM 버전 비교는 검증하지 않는다. 기존 소스와 테스트를 참고한 재설계이며 독립 클린룸이나 선행 저작권 해결을 주장하지 않는다.

## D-038 다중 형식 작업과 복합 실행 예산 (1.16.0)

- 사용자가 제공한 성장 가이드를 기존 스킬과 대조하고, 공통 근거의 산출물별 대조와 선택형 시각 평가를 독립 스킬의 참고 문서로 추가했다. 수치 배점은 합의된 실험에서만 사용하며 실제 시각·독립 검토의 증거를 대신하지 않는다.
- 평가기는 호출 수와 시간 상한을 함께 받고 먼저 도달한 상한에서 중단한다. 폴더 준비 후에 시간이 소진되면 CLI를 시작하지 않고 미실행으로 기록한다. 비용 상한, OS 격리, 자식 프로세스 중단, 재개·체크포인트 기능은 구현하지 않았다.
- 후보 저장소는 메타데이터를 확인했으나 외부 코드·자산을 이 변경에 반입하거나 별도 실행기를 설치하지 않는다. 자료별 재사용 권리와 기존 이력의 미확인 범위는 그대로 남는다.

## D-039 후속 대화와 프로세스 수명 관리 (작업 트리)

- 첫 턴 검사와 후속 대화 검증을 분리한다. 별도 `dialogue_eval.py`는 사전 지정한 두 턴을 동일한 세션과 작업 폴더에서 실행하고 각 호출을 예산에 포함한다. 세션 일치, 첫 턴 스킬 로드, 자동 조건과 로컬 파일·스킬 트리 스냅샷을 각각 기록한다. 자동 검사는 의미 정확성을 판정하지 않는다.
- Windows의 평가 프로세스는 Job Object에 할당되기 전 실제 명령을 시작하지 않는 부트스트랩을 거친다. 제한 시간이나 감독 프로세스 종료 시 Job 핸들을 닫아 해당 Job의 프로세스를 종료한다. POSIX는 별도 세션의 프로세스 그룹을 종료한다. OS 경계와 이탈 경로는 `EVALUATION.md`에 명시한다.
- 두 구현 모두 Python 표준 라이브러리와 운영체제 API로 작성했다. 외부 구현 코드를 복사하거나 새로운 런타임 의존성을 추가하지 않는다. 예외·플랫폼별 실행 및 과거 이력의 법적 권리 상태는 별도로 검증한다.
# 라이선스 범위 표기 (2026-11-19)

`visual-design`의 MIT 범위와 하위 검사기의 Apache-2.0 예외를 양쪽 README에 함께 표시한다. 별도 설치 의존성은 저장소에 포함된 코드와 구분하고 실제 설치 버전별 고지를 확인한다. 과거 RHEL 자료는 원본·권리자·이용 허락을 확인하기 전 재작성만으로 권리 문제가 해결됐다고 판단하지 않는다.
