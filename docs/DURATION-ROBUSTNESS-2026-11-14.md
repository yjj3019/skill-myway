# 장애 시간 표현의 경계 평가 계약

기준: 기존 공개 사례에서 Claude가 `조건부 확정`이라는 혼동 가능한 제목을 사용했다. 날짜·시간대가 확인되지 않으면 가정의 내용을 제목과 계산에 표시하고 확인된 시간은 불필요하게 미확인으로 바꾸지 않는 지침을 추가했다.

사전 고정한 공개 개발 과제 4개: 날짜·시간대 미확인, 같은 날짜의 완전 복구, 자정 경과, 간헐 영향 구간. `tests/eval_cases/duration-boundary-cases.json`과 수동 기준 `tests/eval_cases/duration-boundary-rubric.md`를 사용한다. 자동 문자열 검사는 시간 관계를 검증하지 않으므로 실행 결과를 각각 직접 대조한다.

최종 1.16.6 스킬 본문을 Claude와 Codex에 직접 제공해 각 4회, 총 최대 8회 호출한다. 사례당 timeout 120초. 첫 결과를 본 뒤 지침을 바꾸지 않으며, 실패·시간 초과를 분모에서 제거하지 않는다. 기준본과 통제된 쌍별 비교가 아니며 공개 사례의 단회 자체 검토다. 독립 검토, 자동 로드, reference 접근, Grok, 미노출 사례와 전반적 능력 향상은 이 실험으로 입증하지 못한다.

## 실행 결과와 자체 검토

- Claude·Codex 각각 4회, 총 8회가 모두 종료 코드 0으로 응답했다. `incident-rca/SKILL.md`의 실행 전후 해시는 일치했다. 모델 정확한 버전·비용과 두 환경의 완전한 동등성은 확인하지 못했다.
- 미확인 날짜 사례에서 양쪽 모두 34분을 같은 날짜·시간대라는 가정에 한정하고 전체 지속 시간과 누적 영향의 무조건적 하한을 두지 않았다. Claude의 제목은 `가정 하의 계산`이었다.
- 확인된 시작·완전 복구는 두 응답 모두 34분으로 산출했다. 자정을 넘긴 사례는 두 응답 모두 20분으로 산출했다. 간헐 영향 사례는 양쪽 모두 총 경과 55분과 누적 영향 15분을 구분했다.
- 자체 수동 대조에서 이 8개 응답에 해당 4개 공개 사례의 필수 실패 조건은 발견되지 않았다. 독립 평가자가 아니고 이전 답변을 보고 만든 개발용 사례이며, 동일 조건의 기준본과 비교하지 않았으므로 실제 일반 성능 개선이나 최고 성과를 입증하지 않는다.
- 모델 출력과 상태는 프로젝트 안 `eval-results/duration-boundary-20261114/`에 보존했다. 실제 자동 스킬 로드, 원격 쓰기 차단, Grok, 미노출 사례와 장기·다른 도메인 과제는 미검증이다.
- Windows 최종 전체 회귀는 242건 중 실패 1·skip 0이었다. 4초 시간 초과 테스트에서 손자 프로세스의 시작 표식이 시간 안에 생성되지 않았으며, 기존에 반복 관찰된 시작 지연 증상이다. 원인은 확정하지 못했고 이전 통과 결과로 대체하지 않는다. 같은 방식의 재시도는 중단했다.
