# 라이선스·출처 검토

기준일 2026-11-01. 당시 이 저장소의 기본 라이선스는 Apache-2.0이었다. 통합 검토 대상 저장소의 라이선스 상태와 반영 방식을 기록한다. 현재 적용 범위는 아래 MIT 전환 기록을 확인한다.

## MIT 전환 범위 (2026-11-11, 작업 트리)

- 사용자 요청에 따라 이번 작업에서 새로 작성한 독립 `document-authoring`, `visual-design` 스킬의 배포 라이선스를 MIT로 지정하고 각 디렉터리에 MIT 본문을 넣었다. 그 외 저장소와 플러그인 기본 라이선스는 Apache-2.0으로 유지한다. 스킬 ZIP과 복사 설치본은 해당 스킬의 LICENSE를 우선하며, 명시한 라이선스 파일이 없거나 MIT 표시와 본문 첫 줄이 일치하지 않으면 다른 라이선스로 대체하지 않고 중단한다. 이 검사는 전체 본문의 적법성·권리 보유 여부를 보장하지 않는다.
- 스킬별 MIT 표시는 이번 전환 범위를 명시하는 것이다. 원본의 요구사항·방법론을 참고했고, 고정 길이 문자열 대조는 번역·구조적 유사성·권리관계를 증명하지 않는다. 외부 원문의 보호되는 표현 또는 제3자 권리의 포함 여부가 확인되면 그 권리와 조건을 별도 검토한다.
- 나머지 스킬·코드 전체를 MIT 전용으로 전환할 만큼 선행 권리가 확인되지는 않았다. 특히 과거 RHEL 자료는 원본 미러를 확보하지 못했고 사용자는 기존 자료 소유를 알렸으나 그 이전 권리관계는 확인할 수 없다고 밝혔다. 기존 Apache-2.0의 고지 및 공개 과거 이력은 소급 변경하지 않는다.
- 실제 원본의 저작물·기여자·양도·이용허락을 확인하고 필요한 재구현과 검토를 마친 뒤 파일별 범위를 확정해야 한다. 단일 MIT 표시는 그 전에 하지 않는다. 이 기록은 법률 의견이나 권리 보증이 아니다.

## 사용자 제공 성장 가이드 반영 (2026-11-11, 작업 트리)

- 사용자가 제공한 작업 목표·검증 원칙을 기존 스킬과 평가기 요구에 맞게 작성했다. 외부 저장소의 코드·프롬프트·문장·글꼴·이미지·서식 파일을 복사하거나 의존성으로 설치하지 않았다.
- 후보 33개의 GitHub 저장소 수준 메타데이터를 확인했다. 자동 라이선스 감지는 개별 파일의 라이선스나 권리 확인이 아니며 실제 도입 전 고정 커밋, 제3자 고지와 조건을 별도 점검해야 한다. 범위는 `docs/GROWTH-WORKFLOW-2026-11-11.md`에 있다.
- `document-authoring`과 `visual-design`에 새로 추가한 참고 문서는 각 스킬의 MIT 선언 범위에 속한다. 선행 자료의 실질 유사성이나 권리를 완전히 판별한 결과는 아니며, 이 선언은 과거 공개 이력의 미확인 문제를 해결하지 않는다.

## 원칙

1. **원문을 복사하지 않는다.** 통합한 문구는 이 저장소에서 새로 작성하고, 참고한 개념과 구성만 반영한다.
2. **라이선스가 확인되지 않은 자료는 옮기지 않는다.** 라이선스 파일이 없는 공개 저장소는 기본적으로 저작권자 권리가 유보된 상태로 본다. 같은 작성자의 저장소라도 이 저장소의 Apache-2.0이 자동으로 적용되지는 않는다.
3. **권리 범위가 섞인 자료는 제외한다.** 제3자 원문·인용·과거 기록이 섞였거나 재배포 허락이 확인되지 않은 경로는 통합하지 않는다.
4. **특정 대상이 보이는 자료는 제외한다.** 실명, 고객사, 조직, 내부 시스템, 실제 게시물 인용문이 포함된 자산은 저장소에 넣지 않는다.
5. **예시는 가상 값만 쓴다.** 실제 CVE·RHSA·계정·호스트·주소를 쓰지 않는다.

- 과거에 라이선스 미확인 자료를 전혀 옮기지 않았다는 포괄 주장은 2026-11-08 RHEL 미러 감사에서 반증됐다. `redhat-cve-analysis` 유래 RHEL 자료가 저장소 최초 커밋에 들어 있었고, 최신 main에는 후속 clean-room 교정이 적용됐지만 이전 커밋·태그에는 옛 블롭이 남아 있다. 상세 근거와 한계는 아래 RHEL 계보 감사와 D-020 정정 주석을 따른다.

## 제3자 고지

2026-11-01 당시 통합에서 작성자는 외부 원문의 문장·코드·템플릿을 복제하지 않았다고 기록했다. 이는 해당 당시의 기록이며 이후 콘텐츠 전체의 유래나 제3자 권리를 법적으로 확정하지 않는다. 실제 원문이나 파생물을 배포하는 경우 해당 라이선스와 권리자 고지·변경 표시를 별도로 확인한다.

### 개별 배포물 재점검 (2026-11-11)

- 기존 개별 스킬 ZIP은 저장소 루트의 Apache-2.0 본문을 포함하지 않았다. 독립 배포물에서 수신자가 라이선스 조건을 확인할 수 없는 문제를 보완해 ZIP과 복사 방식 설치본에 스킬 자체 LICENSE가 있으면 이를, 없으면 저장소 LICENSE를 포함한다. 플러그인 배포 폴더에도 루트 LICENSE와 동일한 본문을 추가한다. 심볼릭 링크 방식은 원본 폴더를 참조하므로 별도 복사본이 아니다.
- 라이선스 본문 포함은 원본 유래·권리자 고지·변경 표시나 제3자 자산의 이용 권한 확인을 대체하지 않는다. 해당 조건의 적용 여부와 개별 배포 경로의 권리는 별도 판단한다. 이전에 배포된 ZIP이나 공개 이력은 이 수정으로 바뀌지 않는다.
- AI-Harness 고정 커밋의 트리에서 루트 Apache-2.0과 하위 `design-evidence-harness` MIT 라이선스를 확인했고 별도의 NOTICE 파일은 찾지 못했다. 해당 트리 밖의 자료나 제3자 권리까지 확인한 것은 아니다.
- 2026-11-11 GitHub 메타데이터에서 참고 저장소는 비공개, 이 저장소는 공개 상태였다. 공개된 출처 문서에는 참고 저장소 이름과 경로·구조 정보가 기재되어 있다. 공개 권한이나 기밀유지 약정은 라이선스 표시만으로 확인할 수 없으므로 권리자가 별도 검토해야 한다.
- 기존 RHEL 원본의 과거 블롭과 유래는 아래 계보 감사에 기록된 미해결 위험이다. 이 문서는 침해 여부나 이용 허락을 법적으로 판정하지 않는다.
- 조건 원문: [Apache-2.0 제4조](https://www.apache.org/licenses/LICENSE-2.0), [MIT 허가문](https://opensource.org/license/mit). 적용 범위는 실제 포함·수정된 저작물과 권리관계에 따라 판단한다. 한국에서의 저작물·2차적저작물 판단에는 [저작권법](https://www.law.go.kr/lsInfoP.do?lsiSeq=285693) 등 적용 법률을 확인해야 한다.

### 재검토와 배포 로직 보강 (2026-11-11)

- 당시 Apache-2.0 유지: 프로젝트 라이선스를 바꾸는 것만으로 타인의 권리를 새로 취득하거나 기존 배포·공개 이력을 소급 정정할 수 없다. 이후 사용자 요청에 따른 신규 스킬의 부분 MIT 전환은 문서 상단에 별도로 기록한다.
- 기존 이력과 현재 RHEL 파일을 재비교했다. 과거 `ab5fcf2`와 현행 검사기·보고서 형식 파일에 연속 일치가 있으나 이는 같은 프로젝트의 이전 버전과 비교한 결과다. 권리 미확인 원본과의 동일성을 뜻하지 않는다. 기록된 과거 미러는 이 환경의 확인된 경로에서 찾지 못해 원본 대조·권리관계를 이번에 재검증하지 못했다.
- 이전 정정 이력과 미확인 범위는 보존한다. 권리자·기여자 및 실제 이용허락, 현재 파일의 파생 여부, 공개된 과거 블롭과 이미 배포된 사본의 처리 범위는 확인되지 않았다. 독립 법률 검토와 원본 확보가 필요하다.
- 사용자 진술(2026-11-11): 기존 자료는 사용자가 소유하지만 그 이전의 권리관계는 확인할 수 없다. 이 진술은 선행 제3자 자료의 권리와 재배포 허락을 확인한 것으로 취급하지 않는다.
- Git 작성자 통계에는 사용자 계정의 서로 다른 표기와 자동화 도구 명의가 나타난다. 커밋 작성자 표기는 저작권자, 고용관계, 선행 자료 권리 또는 재라이선스 동의를 증명하지 않는다.
- 배포 안전장치: 저장소 검증기가 루트 라이선스와 플러그인 배포본의 사본을 비교한다. 복사 설치는 스킬별 라이선스가 없으면 루트 본문을 사용하고, 필요한 본문이 없거나 비어 있으면 기존 설치본을 교체하기 전에 중단한다. 독립 스킬 ZIP에도 비어 있지 않은 본문을 넣는다. 이 검사는 라이선스 내용의 권리 귀속이나 제3자 저작물의 허가를 판정하지 않는다.

- 과거 이력과의 비교에서 긴 구현 구간이 남아 있던 `rhel-cve/scripts/check_report.py`를 입력 정규화·단건/통합 규칙·표 검증을 나누는 구조로 다시 작성했다. 단건 보고서는 제목의 CVE와 파일명도 대조한다.
