# 재현 가능한 품질 입증 준비

상태: **평가 설계 및 공개 개발 자료 준비, 최고 성과 미입증**. 이 문서는 측정 가능한 비교의 계약이며 실험 결과나 품질 개선을 선언하지 않는다.

## 공통 실행 계약

1. 기준선과 후보의 전체 스킬 트리·하네스·요청·판정 기준을 각각 해시한다. 모델 버전·권한·도구·호스트·렌더러·글꼴과 호출·시간·비용 상한을 실측해 기록한다. 기준선은 확정된 스냅샷에서 프로젝트 소유의 별도 작업공간으로 읽기 복사하고 기존 미커밋 파일을 덮어쓰지 않는다. 스냅샷과 런타임 로드가 다르면 해당 비교는 보류한다.
2. 같은 과제·모델·설정·예산에 대해 기준선과 후보를 한 쌍으로 실행한다. 실행 순서를 교차하고 예정·미실행·시간 초과·실패를 분모에서 보존한다. 모델 자체의 우열과 지침 변경의 효과는 별도 질문이다.
3. 공개 개발 사례는 `tests/eval_cases/all-skill-measurement-cases.json`과 `tests/eval_cases/duration-regression-cases.json`을 사용한다. 기준선/후보의 미실행 장부는 `tests/eval_cases/all-skill-paired-template.json`이며 `scripts/compare_evaluations.py`로 형식과 분모를 확인한다. 장부의 선언 일치·자동 문자열 통과는 결과의 사실성이나 품질을 인증하지 않는다.
4. 개발에 사용하지 않은 최종 과제와 테스트를 별도 준비해 실행 전에 고정한다. 이 저장소의 사례는 전부 공개되어 있고 결과를 보고 조정한 사례도 있으므로 독립 최종 평가가 아니다. 미노출 자료가 없으면 최종 평가는 NOT VERIFIED다.
5. 사용자에게 보일 산출물은 요청·근거·출력·실행 로그·렌더·판정 기록을 연결한다. 독립 판정자가 없으면 자체 검토로 표시한다. 부정행위·비밀 노출·외부 쓰기 등은 승인된 범위와 실제 OS 권한으로 통제하고, 프롬프트나 작업 폴더를 보안 격리로 취급하지 않는다.

## 코딩 평가

`docs/ALL-SKILL-MEASUREMENT-PLAN.md`의 8개 고난도 과제 명세에 따라 다중 모듈 기능·원인 분석·동시성·복구·경로 경계·성능·호환성·불완전 요구를 각각 독립된 가상 프로젝트로 제작한다. 각 과제는 시작 상태에서 재현 가능한 실패와 요구 계약, 입력 불변성, 숨겨진 평가 테스트의 신뢰성 확인, 비파괴 작업 경계를 갖춰야 한다. 아직 이 8개 fixture와 미노출 평가는 구현되지 않았다.

첫 공개 개발용 과제로 `benchmarks/ledger-pilot/`을 추가했다. 가상 원장의 중복 요청·실패 후 재시도·입력 검증·동시 이체·스냅샷을 다룬다. 의도적으로 결함이 있는 기준 구현은 공개 검사 6개에서 실패했고, 별도로 작성한 양성 대조는 6개를 통과했다. 이 결과는 검사기가 두 통제 구현을 구별한 증거에 한하며 모델 평가·안전성이나 미노출 테스트의 증거가 아니다. 위 8종 전체 fixture는 여전히 미완성이다.

기록 단위는 과제별 실행 성공·기능 검증·회귀·안전 실패·시간·호출 수·비용이다. 성공률에는 예정 건수와 미실행 건수를 함께 제시한다. 사람 기준 소요시간이 확보된 과제에서는 난이도 지표로만 활용하고 모델의 보편적 자율성으로 확대하지 않는다.

## 디자인 평가

동일한 가상 근거·수치·독자·형식에서 비교·변화·구조·HTML·DOCX·PPTX 과제를 수행한다. 각 출력은 실제 사용할 크기와 렌더러에서 전체 페이지를 확인한다. 자료 정확성, 질문에 대한 답, 정보 위계, 타이포그래피·가독성, 시각적 완성도를 사전 루브릭으로 독립 평가한다. 과밀·잘림·숫자 오류·잘못된 연결을 필수 결함으로 따로 보고한다. 현재 6종 과제와 독립 평가자는 미준비다.

HTML과 PPTX의 동일성은 공통 모델·지원 범위·구조 대조·각 출력의 실제 렌더와 편집성 검증을 요구한다. 이 저장소에 공통 출력 모델이 구현됐다고 가정하지 않는다. HWPX·스크린리더·반응형 상태는 별도의 실행 증거가 있을 때만 통과로 둔다.

## 채택·기록

예비 평가 후 표본 수와 개선 기준을 최종 실행 전에 고정한다. 최소한 명백한 안전·사실 오류가 없어야 하고, 쌍별 개선·악화·동일·미판정 수를 모두 제시한다. 작은 표본의 차이를 확정적 순위로 쓰지 않는다. 특정 범위에서의 결과만 말하며, 외부 경쟁 대상·동일 조건과 충분한 독립 증거가 없으면 `최고`라는 상대적 주장도 판정 보류한다. 변경 근거·반증·비용·남은 위험을 기록하고, 공개 개발 사례에 맞춰 사후 조정한 기준은 최종 평가에서 분리한다.
