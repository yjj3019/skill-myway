# 전체 스킬과 평가 하네스 병목 검토

검토일: 2026-11-14. 범위는 이 저장소의 11개 스킬, 스킬에 포함된 실행 코드, 공통 평가 하네스다. 다른 저장소의 실행 상태는 포함하지 않는다. 아래에서 코드로 확인한 위험, 제한된 조건에서 측정한 값, 아직 측정하지 않은 가능성을 구분한다. 지연을 줄이기 위해 품질 검증이나 안전 경계를 생략하는 것을 권고하지 않는다.

## 우선순위별 발견 사항

1. **높음 — CVE 다건 조회에서 외부 장애가 순차적으로 누적될 수 있다.** `plugins/myway/skills/rhel-cve/scripts/epss_kev.py`의 `query_ep_first`는 100개 단위로 요청하고 `lookup`은 미해결 항목마다 `query_backup`을 순차 실행한다. KEV 요청도 별도다. 전체 작업에 적용되는 공통 마감시간은 없다. 네트워크 호출을 즉시 실패하도록 대체한 실험에서 CVE 1/10/101개는 각각 3/12/104회 호출을 시도했다. 실제 API 장애와 경과시간을 측정한 결과는 아니다. 호출별 소켓 timeout은 작업 전체의 최대 실행시간을 보장하지 않는다. **개선:** 전체 시간 예산과 서비스별 제한된 동시성, 예산 소진 시 미확인 결과를 명시하는 방식을 검토하고 실패·부분 결과와 서비스 이용 제한을 보존한다.

2. **높음 — 장문 매뉴얼 생성 외부 프로세스에 명시적 시간 제한이 없다.** `plugins/myway/skills/office-docs/scripts/long-manual/fbuild.js`의 LibreOffice 및 Python 호출과 `gen_toc.py`의 `pdftotext` 호출에 timeout이 없다. 외부 프로세스가 멈추는 상황에서는 해당 작업도 오래 기다릴 수 있다. 또한 `fbuild.js`는 OS 임시 디렉터리에 작업 디렉터리를 생성하며 정리 절차가 보이지 않는다. 이 사용자의 작업 경로 제한과 맞지 않을 수 있다. 실제 무한 대기는 재현하지 않았다. **개선:** 사용자 프로젝트 내 명시적 작업 경로를 사용하고, 전체 시간 예산과 프로세스 트리 종료·부분 결과 처리·도구 소유 파일만 안전하게 정리하는 정책을 추가한다.

3. **중간 — 평가 하네스의 시간 예산은 전 단계의 엄격한 벽시계 상한이 아니다.** `scripts/run_eval.py`에서는 자동 manifest 준비 등이 타이머 시작 전 수행되고 작업 디렉터리 준비 중의 지연은 준비 후에 확인한다. `scripts/dialogue_eval.py`도 준비 단계가 끝난 후 마감 여부를 확인한다. 결과 수집과 정리에도 추가 시간이 걸릴 수 있다. 이는 시간 초과 후 모델을 반드시 시작한다는 뜻은 아니다. **개선:** 예산의 시작과 대상 단계를 명시하고 준비·실행·수집·종료를 각각 계측해 중단 가능한 작업에는 남은 시간을 전파한다. OS 수준에서 중단을 보장할 수 없는 구간은 별도로 표기한다.

4. **중간 — 목차 추출에서 같은 페이지 텍스트를 반복 정규화한다.** `gen_toc.py`는 제목마다 각 페이지를 다시 정규화한다. 제목과 페이지가 많고 제목을 못 찾는 경우 작업량이 커진다. 합성 입력 100개 제목, 100페이지, 페이지당 3,200자에서 현재 방식은 0.621초, 페이지 정규화를 한 번만 하는 비교 구현은 0.010초였으며 결과는 같았다. 각 1회 측정이고 파일 입출력과 PDF 변환은 제외되어 실제 문서의 개선폭을 뜻하지 않는다. `pdftotext` 결과를 한꺼번에 메모리에 담는 점도 대형 문서에서 확인이 필요하다. **개선:** 의미를 보존하는 페이지별 정규화 재사용을 검토하고 실제 문서 크기 및 메모리 사용량을 측정한다.

5. **중간 — 평가 케이스 준비가 전체 스킬 트리 크기와 실행 횟수에 비례해 반복된다.** `scripts/run_eval.py`의 작업 디렉터리 준비는 일부 어댑터에서 스킬 트리 해시 계산과 복사를 반복한다. 현 로컬에서 11개 스킬 해시 계산 세 차례는 각각 약 0.065/0.063/0.075초였다. 복사 시간과 모델 호출 시간은 이 수치에 포함되지 않으며 실제 병목이라고 단정할 수 없다. **개선:** 준비 단계 시간과 복사량을 먼저 계측한다. 선택 스킬만 복사하는 최적화는 자동 선택, 교차 스킬 의존성과 격리를 손상할 수 있으므로 동등성을 먼저 검증한다.

6. **중간 — 독립 평가도 기본적으로 순차 호출되어 총 소요시간이 누적된다.** `scripts/run_eval.py`의 반복 케이스 실행은 순차적이다. 이전에 저장된 실모델 개별 호출 기록 22건에서 Claude 11건의 중앙값은 52.65초, Codex 11건은 61.61초였다. 각 기록은 모델 호출만 분리한 값이 아니고 환경과 작업이 서로 달라 모델 비교나 현재 전체 하네스 실행시간의 대표값으로 사용할 수 없다. 이 검토에서 새 실모델 호출은 하지 않았다. **개선:** 독립 케이스에 한해 제한된 병렬 실행을 실험하고 서비스 제한, 비용, 시간 예산, 파일 격리, 결과 순서 및 재현성을 함께 검증한다.

7. **낮음 — Windows 프로세스 시작과 호스트 부하가 짧은 시간 제한에 영향을 줄 수 있다.** 현재 환경에서 빈 Python 자식 프로세스 세 번의 시작·종료 시간은 약 1.437/1.288/1.751초였다. 다른 작업이 함께 실행된 소규모 표본으로 OS 또는 원인의 단정이나 장기 지연 분포 추정은 불가능하다. **개선:** 시작·실행·정리 시간을 구분해 반복 측정하고 안전한 프로세스 격리와 종료 보장을 약화하지 않으면서 적절한 시간 예산을 설정한다.

## 11개 스킬별 검토

| 스킬 | 지연 가능 경로 | 관측 상태 및 다음 측정 |
| --- | --- | --- |
| code-review | 큰 diff, 광범위한 파일 탐색과 테스트 | 실행시간 미측정. 변경 크기별 탐색·검증 시간을 분리한다. |
| devlog | Notion 조회·기록, 연결 실패 또는 응답 대기 | 외부 서비스 미호출. 각 읽기·쓰기 지연과 실패 상태를 분리한다. |
| document-authoring | 자료 수집과 형식별 생성·렌더·검토 | 실문서 시간 미측정. 형식과 페이지 수별 생성·검증을 측정한다. |
| evidence-first | 근거 수집, 검증 명령 및 독립 확인 | 실작업 시간 미측정. 중복 실행을 측정하되 증거 게이트는 유지한다. |
| incident-rca | 대량 로그·시계열 탐색과 상관 분석 | 실로그 시간 미측정. 입력량과 조회 단계를 기록한다. |
| office-docs | 변환 프로세스 대기와 장문 목차 추출 | 코드상 timeout 부재 및 합성 CPU 실험 확인. 실제 문서와 렌더를 따로 측정한다. |
| prompt-engineering | 반복 평가와 모델 호출 | 개별 스킬 실측 없음. 반복 횟수·토큰·품질을 함께 기록한다. |
| research-brief | 다수 출처 조회와 근거 검증 | 외부 조회 미실시. 출처별 요청 시간 및 실패를 기록한다. |
| rhel-cve | EPSS·KEV 및 백업 조회 | 실패 모의 호출 수 확인. 실제 지연 및 서비스별 제한은 미측정이다. |
| visual-design | 뷰포트별 렌더, 이미지 생성·시각 검토 | 시각 작업 미실측. 생성과 실제 검토를 분리하고 렌더 게이트를 유지한다. |
| writing | 자료·문체 참조, 초안 및 교정 반복 | 실작업 시간 미측정. 참조 로드·모델·교정 단계를 분리한다. |

스킬 파일의 크기나 참조 파일 수는 실제 토큰 수나 호출 지연의 측정값이 아니다. 많은 스킬은 지침이므로 실행 시간은 모델, 도구, 입력과 실제 수행 경로에 따라 달라진다.

## 권장 실측 순서와 완료 기준

1. 각 실행에 공통 ID와 단계별 단조시계 경과시간, 입력 규모, 성공·실패·미검증, 외부 요청 수와 재시도 수를 기록한다. 민감정보와 본문은 불필요하게 기록하지 않는다.
2. CVE 다건 모의 장애에서 전체 예산, 부분 결과, 데이터의 미확인 표현을 확인하고 허용된 범위에서만 실제 네트워크 지연을 측정한다.
3. 장문 문서는 프로젝트 내부 작업 공간에서 작은 문서와 큰 문서를 사용해 변환·목차·렌더·메모리를 따로 측정하고, 인위적 프로세스 지연과 안전한 정리를 검증한다.
4. 평가 하네스는 준비·모델 실행·결과 수집을 분리해 동일 입력과 환경으로 여러 번 측정한다. 중앙값과 상위 지연, 실패율 및 비용을 함께 제시한다.
5. 변경 전후 동일 과제와 품질·안전 게이트로 비교한다. 관측되지 않은 개선율이나 모델 간 우열은 보고하지 않는다.

이번 검토는 위 보고서 작성 외에 스킬이나 하네스를 수정하지 않았다. 각 개선안은 구현 및 회귀 검증 전의 제안이다.
