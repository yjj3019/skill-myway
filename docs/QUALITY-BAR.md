# 품질 기준

이 저장소가 "배포 가능"이라고 부르는 최소 조건이다. 기준을 낮추려면 근거와 결정 기록이 필요하다.

## 필수 기준

| 영역 | 기준 |
|---|---|
| 테스트 | `python scripts/run_tests.py` 실행 수 > 0, 실패 0, **skip 0** |
| 구조 검증 | `python scripts/validate_repo.py` PASS |
| 버전 | `VERSION`과 매니페스트 5곳 동기화 |
| 스킬 형식 | SKILL.md ≤ 500줄, description ≤ 1024자, name = 디렉터리명 |
| 참조 | SKILL.md의 `references/`·`scripts/` 경로가 모두 존재 |
| 라이선스 | 출처·허가·적용 조건을 기록하고, 문자열 대조는 범위를 밝힌 보조 검사로 취급 |
| 민감정보 | 실제 CVE/RHSA·이메일·IP·홈 경로·토큰 0건 |
| 플랫폼 | Claude·Codex·Grok 매니페스트 검증 및 설치 확인 |
| CI | 3 OS × Python 3.11·3.12·3.13 매트릭스 통과 |

## 약화 신호

다음이 보이면 기준을 낮추려는 시도로 보고 차단한다.

- 테스트 skip·삭제, 단언 제거, 커버리지 제외 추가
- `@ts-ignore`·`eslint-disable`·`# noqa`·`# type: ignore`의 무근거 추가
- stub·TODO로 통과시키기, 예외 삼키기
- 임계값·타임아웃·재시도 횟수를 근거 없이 낮추기
- 검증 범위를 줄여 통과시키기(실행 수 감소, 검사 제외)

## 변경 절차

1. 변경 범위에 맞게 위 기준을 실행한다.
2. 실패·skip이 있으면 완료로 보지 않는다.
3. 기준 자체를 바꾸려면 `docs/DECISIONS.md`에 이유를 남기고, 약화인지 개선인지 구분한다.
4. 릴리스는 기준 통과 후에만 한다.

## 한계

- 이 기준은 형식·구조·설치·자동 검사 중심이다. 모델 출력의 의미 품질은 별도 평가(`docs/EVALUATION.md`)가 필요하다.
- 자동 검사 통과는 사실 정확성·보안 취약점 부재를 보증하지 않는다.
