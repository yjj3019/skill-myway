# 기각·보류·거둔 스킬 제안 기록

스킬이나 도구를 새로 제안받거나 외부 저장소에서 반입 후보로 검토했을 때, 기각·보류·거둠으로 끝난 항목과 그 근거를 남긴다. 같은 제안이 다시 올라오면 이 문서에서 이전 판정과 대체 처리를 찾는다. 판정은 그 시점의 범위·라이선스·승인 경계 기준이며, 조건이 바뀌면 다시 검토할 수 있다.

항목 형식: `상태`는 **기각**(제안을 받아들이지 않음), **거둠**(한때 반영했다가 배포에서 제거), **보류**(조건이 갖춰지면 다시 검토)로 구분한다.

## 기술 다이어그램 생성·검증 스킬(기술 스택·아키텍처 표현) — 보류 (2026-11-23)

- 제안 이유: stack-diagram 사례처럼 기술 스택·아키텍처를 HTML·PNG 등으로 표현하고 검증하는 스킬을 신설한다.
- 판정 근거: 2026-11-23 외부 2차 진단. 다이어그램 검토(화살표 방향·신뢰 경계·추정 표시·작은 크기 가독성·로고 권한)는 기존 visual-design의 렌더 검증·외부 자산 권한 확인으로 일부 포괄된다. 로고 권리·외부 조회·토폴로지 정확성은 별도 확인이 필요하다.
- 보류 이유: 반복 수요와 기존 시각 디자인 범위만으로 관리하기 어렵다는 근거가 아직 없다.
- 대체 처리: 기존 평가 사례에서 기존 스킬만으로 놓치는 토폴로지 오류가 있는지 확인하고 visual-design 검토 항목으로 흡수 가능한 부분만 반영한다.
- 재검토 조건: 다이어그램 요청 수요와 놓친 오류 사례가 입증된 후.

## 한국어 자연스러움 통계 도구(korean-naturalness-check) 도입 — 보류 (2026-11-23)

- 제안 이유: 형태소 분석과 코퍼스 빈도로 의심 표현을 찾는 외부 도구를 writing의 보조 신호로 쓴다.
- 판정 근거: 2026-11-23 외부 2차 진단. 코드·문서는 MIT, 코퍼스 파생 DB는 CC BY 4.0 안내이며 시스템 패키지 설치 명령이 포함된다. writing은 이미 '단어 하나나 줄표 하나만으로 AI 작성글로 판정하지 않는다'는 판정 금지 규칙을 둔다.
- 보류 이유: 전문 용어·고유명사·뉴스 코퍼스 편향에 따른 오탐과 의미 변경 위험을 격리 환경에서 측정하기 전에는 유용성을 알 수 없다.
- 대체 처리: 같은 글에 기존 검토와 도구 탐지 결과를 비교하는 실험 후 유용한 신호만 선택 반영한다. 사용자 환경을 직접 변경하기 전에 가상환경과 입력 데이터 보관 범위를 검토한다.
- 재검토 조건: 격리 환경 비교 실험 후 오탐을 감안해도 유용한 추가 신호가 확인된 경우.

## 토큰 최적화 스킬(선행 조사 기반 신설) — 보류 (2026-11-23)

- 제안 이유: 선행 조사를 활용한 토큰 절약 스킬을 별도로 추가한다.
- 판정 근거: 2026-11-23 외부 1차 진단. 스킬 추가보다 같은 작업에서 성공률·오류 누락·토큰·비용을 함께 측정한 뒤 효과가 확인된 규칙만 반영하는 방식을 권고했다.
- 보류 이유: 측정 없이 신설하면 자동 판정 한계에 같은 비용 문제를 반복할 수 있다.
- 대체 처리: 성공률·오류 누락·토큰·비용 측정 항목을 평가 기록에 남기고 효과가 확인된 규칙만 스킬에 반영한다.
- 재검토 조건: 같은 작업의 측정 실행 후.

## 외부 스킬 스캐너(NVIDIA scanning-agent-skills 문서) — 보류 (2026-11-23)

- 제안 이유: 외부 스킬 보안 검토를 위해 명령 실행·외부 통신·의존성·주입 가능성을 검토하는 보조 도구를 평가한다.
- 판정 근거: 2026-11-23 외부 1차 진단. 설치·실행하거나 탐지 정확도를 검증하지 않아 이번에 도입하지 않았다.
- 보류 이유: 설치·실행·탐지 정확도 검증과 라이선스 확인 없이 외부 도구를 의존성으로 두지 않는다.
- 대체 처리: 검토 항목(명령 실행·외부 통신·의존성·주입)을 보조 목록으로만 취급하고 실제 보안 차단으로 간주하지 않는다.
- 재검토 조건: 설치·실행과 탐지 정확도 검증, 권한·라이선스 확인 후.

## admission-helper (진학 도우미) — 거둠 (1.10.0)

- 제안 이유: 대학 모집요강·학생부 성적 분석을 전용 스킬로 제공한다(D-013).
- 판정 근거: `docs/DECISIONS.md` D-013(추가), D-029(제거).
- 기각 이유: 학생부·모집요강 같은 특정 정보는 저장소에 둘 수 없어 스킬이 사실상 질문/답변 우회 절차에 그쳤다. 배포 목록 정리에서 스킬 디렉터리와 함께 제거했다.
- 대체 처리: 스킬 없이 같은 방식(묶음 질문, 확보한 정보만 사용, NOT VERIFIED 구분)으로 답하는 절차를 유지한다.
- 재검토 조건: 특정 정보를 저장소 밖에서 안전하게 받는 경로가 고정되기 전에는 다시 두지 않는다.

## phase-gate·attestation·지식 그래프 평가 — 기각

- 제안 이유: 런타임 하네스의 검증 단계·서명·지식 그래프 평가 개념을 반영한다.
- 판정 근거: `docs/DECISIONS.md` D-014, D-023.
- 기각 이유: 해당 구조는 훅·서브에이전트가 있는 하네스 전용이고 이 저장소에는 Phase 흐름이 없다.
- 대체 처리: 단계 검증과 실패 보존의 개념 중 범용 부분만 `evidence-first`·`docs/EVALUATION.md`에 재작성해 흡수했다.

## ToolBroker·선택 도구 게이트 — 기각

- 제안 이유: 도구 사용을 게이트로 통제하면 선택·측정이 정확해진다.
- 판정 근거: `docs/DECISIONS.md` D-014.
- 기각 이유: 선택 도구는 측정 전에 도입하지 않는다는 원본 문서의 결론을 따랐다.
- 대체 처리: 설계만 문서로 남기고, 도입은 사용자 승인과 권한·격리 확인 후에만 진행한다.

## evidence-first-harness 스킬 — 기각

- 제안 이유: 하네스 전용 evidence-first 워크플로를 스킬로 이식한다.
- 판정 근거: `docs/DECISIONS.md` D-014, D-023.
- 기각 이유: 훅·서브에이전트·ToolBroker에 묶인 절차라 이 저장소 형태와 맞지 않았다.
- 대체 처리: 개념만 `evidence-first` 스킬로 새로 작성했다.

## 에이전트·프롬프트 프레임워크, 코드 리뷰·위임 자산 — 기각

- 제안 이유: 외부 저장소의 에이전트 워크플로와 리뷰·위임 자산을 반입한다.
- 판정 근거: `docs/DECISIONS.md` D-020.
- 기각 이유: 스킬 범위와 맞지 않고 권리 미확정 경로가 섞여 있었다. 특정 조직·개인·실제 게시물이 포함된 문체 자료도 같은 이유로 제외했다.
- 대체 처리: 범용 리뷰 계약과 평가 루브릭은 `docs/REVIEW-CONTRACT.md`·`docs/EVALUATION.md`로 재작성했다. 코드 리뷰·위임 자산은 반입하지 않는다.

## 외부 스킬 전체 이식 (superpowers·agent-skills 등) — 기각

- 제안 이유: 검증·리뷰·디버깅 스킬 모음을 그대로 가져온다.
- 판정 근거: `docs/DECISIONS.md` D-024.
- 기각 이유: 스킬 수·범위·트리거가 기존 12개 스킬과 충돌하고, 전체 이식은 원문 복사 문제가 생긴다.
- 대체 처리: 개념(검증 게이트, 5축 리뷰, 최소 변경, ADR, 품질 기준 약화 탐지)만 기존 스킬의 references와 문서로 재작성했다. 출처는 `docs/LICENSES.md`에 기록한다.

- 판정 근거: `docs/DECISIONS.md` D-025.

- 대체 처리: 시각 증거와 독립 평가 개념만 `visual-design`에 재작성했다.

## 벤치마크·상시 감시·자동 작업·샌드박스 해제 — 기각

- 제안 이유: 자동 감시와 지속 작업이 품질을 높인다.
- 판정 근거: `docs/DECISIONS.md` D-025, D-026.
- 기각 이유: 상시 감시·자동 작업·샌드박스 해제는 사람 판정과 승인 경계를 유지하는 이 저장소의 원칙과 충돌한다.
- 대체 처리: 평가는 예산 상한 안에서만 실행하고, 완료 주장은 사람 확인을 거친다.

## 렌더러·외부 도구 설치 (RENDER-GATE 실행) — 보류

- 판정 근거: `docs/DECISIONS.md` D-031.
- 보류 이유: 설계만 문서로 두고, 외부 도구 설치·모델 실행은 사용자 승인과 권한·격리 확인 후에만 진행하기로 했다. CI의 LibreOffice는 저장소 검사 전용이다.
- 대체 처리: `docs/RENDER-GATE.md` 설계 문서와 구조 검사만 유지한다.

## 검증·릴리스 거버넌스 강제 게이트 — 보류 (일부 흡수)

- 제안 이유: 평가 루브릭, 스킬 호출 평가 케이스, 버전 증가 강제 게이트, 릴리스 기록 형식을 요구한다.
- 판정 근거: `docs/DECISIONS.md` D-020(후속 후보).
- 보류 이유: 형식 강제는 콘텐츠가 아니라 이번 범위에 넣지 않았다.
- 대체 처리: 매니페스트 버전 일치 검사는 `scripts/validate_repo.py`에 흡수했다. 나머지 게이트는 후보로만 남긴다.

## 세션 시작 훅 자동 라우터 — 기각 (2026-11-23)

- 대체 처리: description 트리거와 `scripts/simulate_eval.py` 라우팅 검사를 유지한다. 훅은 도입하지 않는다.

## 자동 승인 프리셋 (acceptEdits 등) — 기각 (2026-11-23)

## Node.js 도구 체인 — 기각 (2026-11-23)

## 도구가 소유한 바이트 보증 (모델 편집 결과 보장) — 기각 (2026-11-23)

- 제안 이유: 도구가 수정 결과의 바이트를 보증하면 회귀를 막는다.
- 판정 근거: 2026-11-23 외부 저장소 분석과 `docs/EVALUATION.md`의 자동 판정 경계.
- 기각 이유: 모델이 만든 산출물의 정확성·의미를 도구가 보증한다고 선언하면 사람 판정과 미검증 규칙과 충돌한다. 자동 검사는 형식·문자열 한정이다.
- 대체 처리: 자동 검사와 사람 의미 판정을 분리하고, 검증하지 못한 항목은 NOT VERIFIED로 남긴다. 재현 명령과 기록을 남기는 방식만 도입 범위로 본다.

## 자동 추론 모드 강제 (thinking 자동 활성화) — 기각 (2026-11-23)

- 제안 이유: 모든 요청에서 추론 모드를 켜면 품질이 오른다.
- 판정 근거: 2026-11-23 외부 저장소 분석.
- 기각 이유: 모델 내부 동작을 자동으로 켜는 옵션은 측정 전 도입·승인 경계 밖이고, 비용 상한과 격리를 보장하지 않는다.

## 검토 절차

- 제안이 되살아나면 이 문서의 판정 근거를 먼저 읽고, 조건 변화가 있으면 새 판정을 위에 추가한다.
- 기각 사유가 사라진 항목만 다시 검토한다. 판정을 뒤집으면 이전 항목에 뒤집은 날짜와 이유를 덧붙인다.
- 이 문서는 기록일 뿐이며, 기록의 존재가 제안 재발을 막거나 모든 검토를 담는다는 보증이 아니다.
