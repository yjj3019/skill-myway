# 오피스 렌더링 게이트 설계 (draft)

이 문서는 실행되지 않은 렌더링 게이트의 요구사항과 후속 단계를 기술한다. `render_check.py`와 자동 레이아웃 검사는 아직 구현되지 않았다.

`scripts/check_office.py`는 가상 PPTX·DOCX·XLSX 샘플을 생성·재열고, 별도의 `inspect_office_file` 함수로 기존 파일의 일부 구조도 검사한다. `run_eval.py`는 지정된 조건의 산출물 검사에 이 함수를 연결한다. XLSX 캐시·수식 검사는 실제 재계산과 다르다. 샘플의 LibreOffice 재계산과 실제 사용자의 파일·Excel 계산도 별도다. **구조 검사는 렌더링(넘침·겹침·폰트 대체·이미지 누락)을 검증하지 않는다.**

> 상태: `render_check.py`와 자동 레이아웃 게이트는 없다. 2026-11-07 가상 샘플 렌더 결과는 당시 시각 리뷰를 수행하지 않았다. 현재 `design_review_gate.py`는 이미 존재하는 원본·이미지·검토 선언의 해시 정합성을 검사하지만 렌더링이나 실제 시각 품질은 확인하지 않는다.

## 1. 게이트 단계

| 단계 | 확인 내용 | 자동/수동 | 현재 |
|---|---|---|---|
| 요구사항 | 독자·목적·발표 시간·고객 템플릿·자료 출처 | 수동 | 지침에 존재 |
| 구조 | 결론형 제목, 슬라이드별 메시지, 주장-근거 연결 | 수동 시각 리뷰 | 지침·시각 리뷰 기준 (자동 검사 없음) |
| 파일 구조 | 슬라이드 수, 제목·문단·표·수식 문자열, 재열기 | 자동(지원 범위) | `check_office.py`의 샘플 생성과 기존 파일 검사; 실제 검사된 파일·필드만 확인 |
| **XLSX 계산 결과** | LibreOffice/soffice 재계산, 수식 캐시, 기대값·오류 | 자동(샘플만) + 범위 명시 | 샘플 10회 반복·10개 가상 수식 시나리오 통과 (2026-11-07) |
| **렌더링** | 한글 줄바꿈, 잘림·겹침, 표 밀도, 그래프 글자 크기, 폰트 대체, 이미지 누락 | 자동 출력 + 수동 시각 판정 | Sidecar로 3장 렌더 가능. 이미지 생성은 확인됐으나 육안 판정·자동 게이트는 없음 |
| 전달 | 요청 형식과 실제 파일 일치, 확인 못 한 항목 표시 | 수동 | 지침에 존재 |

**검사 범위 구분**: `check_office.py`(자동)는 PPTX·DOCX·XLSX 샘플의 존재·일부 구조 검사와 XLSX 샘플 계산 검사를 수행한다. 2026-11-07 시뮬레이션에서 XLSX 샘플 계산 상태가 10/10 PASS로 관찰됐다. 이 결과는 가상 샘플·단일 LibreOffice 환경에 한정되며 실제 파일·Excel 호환성의 증거가 아니다. "제목이 실제로 결론인지", "주장과 근거가 연결되는지", "도형·차트의 편집 가능성 전반"은 **별도 검증 필요**(수동)다. 편집 가능성은 파일을 열어 개체별 수정 가능 여부를 확인한 뒤에만 말한다.

## 2. 렌더링 자동 검사 설계 (신규)

이 저장소에는 `scripts/render_check.py`가 없다. sidecar CLI는 수동으로 렌더 이미지를 만들 수 있으나, JSON의 페이지·폰트 정보와 이미지 육안 검토를 게이트 결과로 저장하거나 합격/실패를 판정하는 자동 파이프라인은 미구현이다.

```text
(향후 제안) render_check.py [--out DIR] [--renderer libreoffice|soffice]
1. check_office.py로 생성한 가상 PPTX/DOCX/XLSX를 렌더러로 PDF(또는 이미지) 변환
2. PDF 페이지 수 = 슬라이드/페이지 수 확인
3. (PPTX) 슬라이드 크기 밖 객체, 빈 슬라이드, 텍스트 박스 겹침(bbox 교차), 표 셀 잘림 지표 수집
4. 폰트 대체·이미지 누락은 렌더러 로그(경고)와 렌더 결과 이미지를 함께 남김
5. 검사 결과를 JSON으로 출력: {file, pages, overflow_hits, overlap_hits, font_warnings, image_missing}
```

- **겹침은 후보 제시만**: bbox 교차를 발견해도 오류로 단정하지 않는다. 배경 위 글자, 아이콘과 원형 배경 등 의도된 겹침일 수 있으므로 후보를 좌표와 함께 남기고 **시각 리뷰로 판정**한다.

- **한계 명시**: 렌더러가 없다면 `NOT VERIFIED`로 끝난다(현재 상태 유지). LibreOffice 렌더링과 실제 PowerPoint 표시는 다를 수 있으므로 환경(렌더러 버전·사용 여부)을 기록한다.
- **가상 사례**: 한글 긴 제목(잘림 후보), 복잡한 표(밀도), 그래프, 이미지, 고객 템플릿(가상)을 포함한 PPTX 픽스처를 만든다. 가상 값만 사용한다.
- 자동 지표는 **사람의 시각 리뷰를 대체하지 않는다.** 자동 결과와 수동 시각 판정을 별도로 기록한다.

## 3. 실제 산출물 재열기 전제

`check_office.py`의 `inspect_office_file`은 기존 PPTX·DOCX·XLSX를 검사할 수 있으며 `inspect_office_artifacts`는 작업 폴더 안의 산출물에 이를 적용한다. `run_eval.py`의 선택적 산출물 검사 경로에 연결돼 있다. 검사를 실제로 실행한 파일과 필드만 구조 검증으로 기록한다. 이 검사는 화면 렌더·편집 가능성 전반·계산 완료·접근성의 증거가 아니다.

## 4. 평가 사례 연결

- `tests/eval_cases/cases.json`의 `office-docs-real-file-03`은 실제 .pptx 생성 요청이며, 렌더링 검사 불가 시 구조 확인 + 미확인 명시를 요구한다. 렌더링 게이트가 생기면 이 케이스의 검사가 자동 지표를 남기도록 연결한다.
- 시각 리뷰는 `tests/eval_cases/visual-review-rubric.md`의 기존 기준을 그대로 쓴다.

## 5. 다음 단계와 검증 기준

1. LibreOffice 계산은 로컬 샘플 수식으로 시뮬레이션했다. 시각 렌더는 설치된 Office sidecar로 수행했고 manifest의 페이지 수·missingFonts를 확인했다. 이미지 내용은 육안 판정하지 않았다.
2. Office sidecar CLI의 manifest·페이지 수·missing-font 정보를 저장소 검증 기록과 연결할 자동 합격/실패 게이트는 없다.
3. 가상 PPTX/DOCX/XLSX fixture로 변환·페이지 대응·기본 오류 처리를 반복한다.
4. 이미지 입력이 가능한 검사자/모델에서 전체 페이지를 확인하고 결과를 기록한다.
5. 전체 페이지를 사람이 검토하고 확인 환경을 기록한다.
6. 실제 PowerPoint 표시와의 불일치 가능성은 NOT VERIFIED로 남긴다.

렌더 파일 생성은 확인했지만 이미지 내용의 사람 리뷰와 자동 레이아웃 게이트는 미실행이므로, 시각 품질은 **NOT VERIFIED**다.
