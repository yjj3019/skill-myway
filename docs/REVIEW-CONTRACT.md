# 리뷰 계약

코드·문서·산출물 리뷰의 심각도와 증거 기준을 통일한다. 리뷰는 "느낌"이 아니라 재현 가능한 근거로 남긴다.

## 심각도

| 심각도 | 정의 | 필요 증거 | 처리 |
|---|---|---|---|
| 차단 | 보안·데이터 손상·회귀. 또는 요구 미충족 | 재현 절차 또는 명확한 근거 | 머지·배포 전 수정 |
| 중요 | 조건부 오동작, 오류 처리 누락, 테스트 약화 | 조건과 영향 설명 | 수정 권장. 미수정 시 사유 기록 |
| 권장 | 가독성·중복·성능 개선 | 개선 전후 비교 | 선택 |
| 질문 | 의도·범위 확인 필요 | 모호한 지점 | 답변 후 재분류 |

## 증거 요건

- 실행한 명령, 환경, 출력(요약)을 함께 적는다.
- 실행하지 못한 검사는 `Validation Gap`으로 분리한다.
- 수치 주장은 측정 조건을 붙인다.
- 스크린샷·로그를 인용하면 원문 위치(파일:줄)를 남긴다.

## 공백(Validation Gap)

- 확인하지 못한 파일·경로, 실행하지 못한 테스트, 재현하지 못한 결함, 환경 제약을 적는다.
- 공백이 결론을 바꾸는지 한 줄로 밝힌다. 바꾸지 않으면 "영향 없음"이라고 쓴다.
- 공백을 확신으로 바꾸지 않는다.

## 리뷰 범위

- 리뷰한 파일과 하지 않은 파일을 나눈다.
- 요청 범위 밖 제안은 `권장`으로 분리한다.
- 같은 세션에서 수정이 반복되면 이전 판정을 다시 확인한다.

## 금지

- 테스트 약화·비활성화로 통과시키기
- 예외를 삼켜 오류를 숨기기
- 생성물·포맷 변경 노이즈를 리뷰 항목에 섞기
- 실행하지 않은 검증을 통과로 보고하기
