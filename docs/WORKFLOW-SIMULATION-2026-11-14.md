# 전체 스킬·하네스 시뮬레이션과 수정

2026-11-14, 1.16.4 작업본. 기존 미커밋 변경 위에 실행기·시험·문서만 보완했다. 이번 작업에서는 스킬 본문과 패키지 버전을 바꾸지 않았다.

## 범위

전체 11개 스킬의 공개 개발 사례 72건을 스키마·커버리지 검사하고, 모든 스킬에 공통 실행기의 10개 시나리오를 적용한다. 같은 입력의 실모델 반복이 아니라 서로 다른 정상·고장 조건의 오프라인 시험이다. 가상 응답을 주입해 실행·판정·집계를 검사하며, 스킬을 모델이 실제로 따르는지 또는 디자인이 아름다운지는 평가하지 않는다.

공개 사례에는 스킬별 입력 누락, 범위 경계, 외부 지시 주입 요청이 포함된다. 해당 요청의 존재와 실행 패킷 생성은 실제 모델의 안전한 처리 증거가 아니다.

|---|---|---|

## 문제와 수정

| 번호 | 문제 | 수정 |
|---|---|---|
| 1 | 일반 평가 manifest에서 산출물 정책·확장자 누락 | 두 필드 보존 및 변경 추적 시험 |
| 2 | 파일 요구에도 생성 금지 프롬프트 적용 | 보존할 작업공간이 있으면 정책별 생성 허용. 보존하지 않는 실행은 생성 금지 |
| 3 | 일반 평가의 필수·금지 파일과 확장자 미판정 | 검사 모드에 정책 적용. 필수 파일은 검사 설정 없으면 실행 거부. 미관측 정책은 미검증 |
| 4 | Codex 오류 이벤트와 종료 코드 0의 조합을 성공 취급 | `turn.failed`·`error`를 실패 처리. 안내 문구 뒤 JSONL도 해석. 후속 대화에도 적용 |
| 5 | 작업공간 준비 실패가 결과를 남기지 못하고 폴더 잔류 | 실패 결과 기록, 도구가 만든 폴더 정리, 모델 미호출 확인 |
| 6 | 산출물 링크를 조용히 제외하거나 스킬 복사 시 따라감 | 링크·Windows 재분석 지점 거부 및 복사 전 트리 검사 |
| 7 | 정상 스킬명과 오타를 함께 선택하면 오타 무시 | 알 수 없는 선택은 실행 전 거부 |
| 8 | 시간 초과와 일반 오류 합산 | `timeout` 상태와 `timed_out` 집계를 별도로 기록 |
| 9 | 늦게 시작한 자손의 지연 쓰기 전에 시험 종료 가능 | timeout 후 관찰을 지연 쓰기보다 길게 유지. 시작 확인·실행 timeout은 유지 |
| 10 | Windows의 중첩 Python 감독기·가상환경 경유가 시작 비용을 누적 | 평가기가 Job을 직접 소유하고 표준 라이브러리 게이트만 기본 Python으로 실행. 요청한 프로그램의 가상환경은 보존 |

## 10개 시나리오

`tests/test_workflow_simulation.py`의 `WorkflowSimulation`은 각 시나리오를 11개 스킬에 적용한다. 총 110개 예정 조합이며 예산 제한 시나리오에서는 1개만 가상 실행하고 10개는 미실행으로 남아야 성공이다. 실모델 110회 호출을 뜻하지 않는다.

1. 정상 자동 조건: 자동 조건만 통과, 의미 품질은 미검증.
2. 빈 응답: 실패.
3. 필수 내용 누락: 실패.
4. 금지 내용 포함: 실패.
5. 최대 길이 초과: 실패.
6. 정상처럼 보이는 응답과 오류 종료: 실패.
7. 시간 초과: 일반 오류와 별도 집계.
8. 필수 산출물 누락: 실패.
9. 잘못된 산출물 확장자: 실패.
10. 호출 예산 소진: 남은 항목을 미실행으로 보존.

추가 회귀 시험은 파일 금지·미관측 정책, 프롬프트·manifest 전달, 오류 이벤트, 준비 실패·정리, 링크 경계, 오타 선택을 검사한다. 링크 시험은 모의이며 모든 파일 시스템을 실증하지 않는다.

## 실행

최종 결과: 저장소 검사 PASS, 공개 사례 72건·11개 스킬 PASS, 전체 테스트 **240건·실패 0·skip 0**. Claude·Codex·Grok 각각 공개 사례 72건과 Codex 자동 선택 10건의 실행 준비도 확인했다(dry-run, 모델 호출 0회). LibreOffice 경로를 해당 프로세스에 지정해 실제 XLSX 재계산·오류 캐시 검사를 포함했다.

```text
python scripts/validate_repo.py
python scripts/simulate_eval.py
python -m unittest discover -s tests -p test_workflow_simulation.py -v
python scripts/run_tests.py
```

결과는 `docs/VERIFICATION.md`의 최신 항목을 따른다. Windows의 기존 Python 환경을 사용하고 임시 파일은 프로젝트 내부 `.git/codex-validation-temp`에 두었다. 배포 자산이 아니다.

## 한계와 출처

- Windows 시작 지연은 최초 재실행에서는 없었으나 전체 회귀에서 다시 발생했다. 단순 가상환경 Python 실행 약 2.013초, 격리 옵션 포함 약 2.238초, 기본 Python 격리 실행 약 1.117초를 관측했다(각 1회, 일반 성능 수치가 아님). 중첩 감독기와 게이트의 가상환경 경유를 제거했다. 종료 시험용 프로그램도 의존성이 없어 기본 Python을 사용하되 별도 시험으로 실제 요청의 가상환경 보존을 확인한다. 4초·10초 제한과 시작 확인은 유지한다. 호스트 전체 지연의 근본 원인이나 모든 부하에서의 시작 시간은 보장하지 않는다.
- 이번에 실제 Claude·Codex·Grok 호출, 독립 의미 평가, 실제 시각 산출물 비교, 원격 POSIX 재검증은 수행하지 않았다. 기존 POSIX 세션 이탈 한계는 남는다.
- 외부 소스·문장·템플릿·이미지·폰트·의존성을 새로 도입하지 않고 현재 입력·실패 계약에 맞춰 직접 구현했다. 기존 라이선스와 권리 미확인 범위를 변경하지 않았다. 법적 무위험 인증은 아니다.
- Windows 설계에서는 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), Python의 [venv](https://docs.python.org/3/library/venv.html)와 [명령 옵션](https://docs.python.org/3/using/cmdline.html)의 동작 설명을 확인했다. 원문·예제 코드는 복제하지 않았다.
- 외부 저장소 쓰기, 컴퓨터 사용 자동화, 커밋·푸시·게시를 수행하지 않았다.
