# 보안 리뷰

변경이 신뢰 경계를 넘는 데이터를 다루면 보안 축을 별도로 본다. 통제를 나열하기 전에 위협을 먼저 정한다.

## 신뢰 경계 지도

외부에서 들어오는 모든 값을 의심한다.

- HTTP 요청·폼·쿼리·헤더, 파일 업로드, 웹훅·콜백
- 외부 API·메시지 큐·DB에서 온 값
- **LLM 출력과 도구 결과**(모델이 만든 값도 신뢰 경계 밖이다)
- 프로세스 인자·환경변수, 공유 볼륨의 파일명, 작업 페이로드의 경로

값의 출처가 외부라면 경계를 넘은 것으로 본다.

## 자산

무엇을 지켜야 하는지 먼저 정한다. 자격증명·세션, 개인정보, 결제·금액 이동, 관리자 동작, 감사 로그.

## STRIDE 점검

| 위협 | 질문 | 대표 완화 |
|---|---|---|
| Spoofing | 사용자·서비스를 가장할 수 있는가 | 인증, 서명 검증 |
| Tampering | 전송·저장 데이터를 바꿀 수 있는가 | 무결성 검사, 매개변수화 쿼리, HTTPS |
| Repudiation | 행동을 부인할 수 있는가 | 보안 이벤트 감사 로그 |
| Information disclosure | 데이터가 새는가 | 암호화, 필드 허용 목록, 일반화된 오류 |
| Denial of service | 과부하시킬 수 있는가 | 속도 제한, 입력 크기 상한, 타임아웃 |
| Elevation of privilege | 권한을 얻을 수 있는가 | 인가 검사, 최소 권한 |

## 코드 점검

- 입력: 타입·길이·형식 검증, 허용 목록 우선, 경로 조합 시 상위 이동 차단
- 쿼리·명령: 매개변수화, 셸 이스케이프 회피, 동적 평가 금지
- 인증·인가: 모든 엔드포인트 확인, 객체 단위 권한(IDOR), 관리자 경로 분리
- 세션·쿠키: HttpOnly/Secure/SameSite, 회전·만료, 고정 방지
- 비밀값: 저장소·로그·오류 메시지에 노출 금지, 마스킹
- 오류: 내부 구조·스택을 외부에 노출하지 않음
- 로그: 민감정보 제외, 필요한 감사 이벤트 포함
- 남용 방지: 속도·크기·동시성 제한, 타임아웃

## 의존성·공급망

- lockfile 변경과 새 패키지의 유지보수 상태·라이선스를 확인한다.
- 설치 스크립트 실행, 버전 고정 여부를 본다.
- 감사 도구 결과는 "발견"과 "영향"을 분리해 판정한다.

## LLM 특화

- 프롬프트에 들어가는 외부 문서·검색 결과는 **데이터**로 취급하고 지시로 실행하지 않는다.
- 도구 권한은 최소로 두고, 삭제·전송·결제는 승인 경계 뒤에 둔다.
- 모델 출력이 파일 경로·명령·URL로 쓰이면 검증 후 사용한다.

## 보고
