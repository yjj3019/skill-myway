# Fallback — Notion MCP 미연결 시

Notion MCP가 비활성이면 기록을 유실하지 않도록 SESSION_LOG.md로 폴백한다.

## 원칙

- **날짜별 누적 append만.** 기존 이력 덮어쓰기 절대 금지.
- 파일 경로: 프로젝트 루트의 `SESSION_LOG.md`
- 저장 결과를 확인한 경우에만 사용자에게 "Notion 미연결 → SESSION_LOG.md 기록함. 추후 수동 동기화 필요"라고 알린다. 저장하지 않았으면 미저장, 성공 여부가 불명확하면 저장 여부 미확인으로 보고한다.
- 확인하지 않은 작업·오류·명령·시각은 지어내거나 없음으로 쓰지 않고 미확인으로 표시한다.

## SESSION_LOG.md append 포맷

```
## 📅 세션 백업: YYYY-MM-DD HH:MM
### ✅ 완료 작업 / 🚧 진행 중 / ⏭️ 다음 세션 즉시 실행 항목
### 🧩 런타임 스냅샷: Branch/Path · Last File · Active Errors · Last CMD
### 💬 인계 메모
```

## 동기화 복구

한 기록의 복구는 한 작업자가 맡는다. 원격 쓰기가 승인된 페이지와 개발 이력 섹션을 먼저 식별한다. 최초 append 전에 무작위 UUID를 한 번 발급해 로컬 원문과 함께 보존하고, 원격 블록에도 같은 ID를 넣는다. 생성 시각이나 제목만으로 기록을 식별하지 않는다.

1. 대상 섹션을 마지막 페이지까지 다시 읽어 같은 ID의 블록 수와 본문을 대조한다. 로컬과 원격의 표준 본문은 ID·동기화 상태 표기를 제외한 같은 평문으로 비교한다.
2. 일치하는 블록이 정확히 하나면 로컬 이력에 해당 ID의 `[synced]` 확인을 덧붙인다. 본문이 다르거나 여러 개면 충돌로 보고 수동 대조한다. 읽기 실패·부분 조회는 보류한다.
3. 일치 항목이 없고 이전 쓰기가 없었거나 적용되지 않았다고 확실히 확인한 경우에만 추가한다. 먼저 로컬에 ID와 `pending`을 남기고 저장을 확인한 뒤 한 번 append한다. 응답 유실·시간 초과·프로세스 중단 뒤에는 1단계로 복귀한다. 결과 불명인 쓰기가 있고 항목이 아직 보이지 않으면 보류한다.
4. ID 없는 예전 백업은 대상 페이지, 시각, 제목, 본문과 이전 시도 기록으로 먼저 대조한다. 기존 원격 기록임이 확인되면 해당 항목을 연결한다. 이전 전송 여부가 불명확하면 보류하고, 확실히 미전송인 항목만 ID를 발급해 진행한다.

판정을 로컬에서 재확인할 때 `python scripts/reconcile.py`의 표준 입력에 JSON 객체를 전달한다(경로는 이 스킬 기준). `entry_id`, `body`는 저장된 식별자와 본문, `state`는 ready 또는 pending, `complete`는 대상 섹션 조회 완료 여부다. `entries`는 원격에서 확인한 추적 블록들의 `entry_id`, `body` 배열이다. 도구는 append, synced, hold, conflict 중 한 동작을 출력한다. 조회와 쓰기는 담당 클라이언트가 수행한다. 서로 다른 작업자의 동시 쓰기에 원격 고유성 제약은 없다.
