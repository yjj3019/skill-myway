# 세션 핸드오프

긴 작업을 새 세션으로 넘길 때 상태를 잃지 않게 기록한다. 새 세션은 이 문서와 `docs/compound-log.md`부터 읽는다.

## 언제 쓰나

- 마일스톤(단계)이 끝나 검증까지 마쳤을 때
- 컨텍스트가 길어져 일관성이 떨어질 때
- 새 단계를 새 세션에서 시작할 때

## 기록 항목

| 항목 | 내용 |
|---|---|
| 마지막 완료 단계 | 무엇을 끝냈고 어떤 검증을 통과했는가 |
| 진행 중 | 어디까지 했고 어떤 파일·브랜치인가 |
| 핵심 결정 | 확정된 선택과 버린 대안 |
| 검증 상태 | 실행한 명령, 통과·실패·skip 수, 마지막 커밋 |
| 열린 이슈 | 미확인·위험·보류 항목 |
| 산출물 | 이번에 만든 파일·문서 |
| 다음 행동 | 새 세션에서 바로 할 일 |

## 규칙

- 확인한 것과 미검증을 분리해 적는다. 미확인은 없음으로 바꾸지 않는다.
- 날짜·커밋 해시·실행 환경(플랫폼·언어 버전)은 확인한 값만 적고, 불명확하면 미확인으로 둔다.
- Notion 또는 로컬 저장과 동기화의 성공 여부를 각각 확인해 보고한다. 초안만 작성했다면 저장했다고 쓰지 않는다.
- CI 상태를 적을 때는 마지막으로 확인한 커밋과 결과만 쓴다. 확인하지 않은 실행을 통과로 쓰지 않는다.
- 중간 작업을 새 세션에서 재개하지 않는다. 다음 행동부터 시작한다.
- 이 기록은 Notion 부모 페이지나 `SESSION_LOG.md`에 같은 구조로 남긴다.
