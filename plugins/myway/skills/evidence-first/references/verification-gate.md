# 완료 검증 게이트

완료·수정·통과를 주장하기 전에 확인하는 절차다. 주장보다 증거가 먼저다.

## 철칙

- **이번 응답에서 실행한 검증만** 근거로 쓴다. 이전 실행, 기억, 추정은 증거가 아니다.
- 검증 명령을 실행하지 않았다면 "통과"라고 쓰지 않는다.
- 규칙의 문구를 피하려고 우회하는 것도 위반이다.

## 게이트 5단계

1. **주장 식별** — 지금 하려는 주장이 무엇인가(테스트 통과, 빌드 성공, 버그 수정, 배포 완료).
2. **증명 명령 결정** — 그 주장을 증명하는 명령은 무엇인가.
3. **전체 실행** — 생략 없이 신선하게 실행한다. 부분 실행·캐시 결과는 안 된다.
4. **출력 읽기** — 종료 코드, 실행 수, 실패 수, skip 수를 직접 확인한다.
5. **판정** — 출력이 주장과 일치하면 **증거와 함께** 주장하고, 아니면 실제 상태를 그대로 보고한다. 실패·skip 등 수치가 출력에 없고 확인 가능한 근거도 없으면 `미확인`으로 표시한다. 명시적 결과나 확인 가능한 집계 없이 0으로 확정하지 않는다.

## 주장별 필요 증거

| 주장 | 필요한 증거 | 불충분한 근거 |
|---|---|---|
| 테스트 통과 | 테스트 명령 출력: 실행 수·실패 0·skip 0 | 이전 실행, "될 것 같다" |
| 린트/검사 통과 | 해당 명령 출력: 오류 0 | 일부만 확인, 추정 |
| 빌드 성공 | 빌드 명령 exit 0 | 린트 통과, 로그가 좋아 보임 |
| 버그 수정 | 원 증상을 재현하던 테스트가 이제 통과 | 코드를 바꿨다, 고쳤다고 생각함 |
| 배포 완료 | 배포 명령 결과 + 배포 후 확인 | 배포 명령을 실행함 |
| 시각적 품질 | 대상 버전의 실제 렌더를 명시한 환경·범위에서 직접 확인한 결과 | 정적 검사 통과, 이미지 파일 생성만 확인 |
| 동작·상호작용 | 대상 환경에서 해당 조작과 결과를 직접 확인한 기록 | 정지 화면, 코드 존재만 확인 |

## 시각 증거의 경계

- 코드·구조 검사는 구현과 속성을, 렌더 확인은 확인한 화면의 외관을, 실제 조작은 실행 경로의 동작을 각각 뒷받침한다. 한 종류의 성공을 다른 종류의 성공으로 바꾸지 않는다.
- 이미지나 스크린샷은 촬영한 버전·환경·상태·영역에 한정된 증거다. 보지 않은 화면, 반응형 상태, 상호작용이나 접근성을 증명하지 않는다.
- 검증 범위와 환경, 실제 관찰 및 실패를 기록한다. 확인하지 못한 항목은 이유와 영향, 필요한 후속 확인을 함께 `미검증`으로 보고한다. 부분 확인을 전체 통과로 표현하지 않는다.

## 환경 명시

- 로컬 통과와 CI 통과는 다르다. 어떤 환경(OS·언어 버전)에서 실행했는지 적는다.
- 실행하지 못한 검사는 `미검증`으로 남기고, 완료 판정에 미치는 영향을 한 줄로 쓴다.

## 금지

- skip·0건 실행을 통과로 보고하기
- 실패를 숨기거나 예외를 삼켜 통과시키기
- 오래된 출력을 현재 결과처럼 인용하기
- 실행하지 않은 검증을 "확인함"으로 쓰기
