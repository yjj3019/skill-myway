아래 골격을 순서대로 채운다. 값이 없는 항목은 지우지 말고 `확인 필요`로 남긴다.
예시 값은 모두 가상이며 실제 사건·조직을 가리키지 않는다.

## 2. 영향

| 구분 | 내용 |
|---|---|
| 대상 | 영향받은 기능·서비스 범위 |
| 규모 | 요청 수, 사용자 수, 지연 등 확인된 값 |
| 기간 | 시작·종료 시각과 시간대 |
| 업무 영향 | 중단·지연·데이터 영향 |

수치는 확인된 출처와 함께 적는다. 추정치는 추정임을 표시한다.

| 2026-01-01 09:40 | 완화 조치 적용 | 변경 기록 | 높음 |

## 4. 확인된 사실

번호를 붙여 적는다. 각 항목에 출처(로그·지표·배포 기록)와 시각을 붙인다.

1. 배포 직후 오류율이 증가했다. (배포 기록, 오류 지표)
2. 특정 조건의 요청에서만 시간 초과가 발생했다. (로그 원문)

## 5. 가설과 검증

| 가설 | 지지 증거 | 반증 | 검증 방법 | 판정 |

## 작성 예시 (가상)

### 1. 요약

- 증상 한 줄: 가상 서비스 A의 목록 조회가 간헐적으로 시간 초과
- 영향 범위와 지속 시간: 전체 요청의 일부, 약 30분
- 확정된 원인 또는 현재 판정: 캐시 만료 직후 동시 요청 증가(가설 단계)
- 신뢰도: 중간
- 즉시 조치 상태: 임시로 동시 요청 수를 제한함

위 예시는 형식 설명용이며 실제 사건의 값이 아니다.
