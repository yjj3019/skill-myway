# 발표자료 근거 검증

슬라이드를 한 번에 전부 만들지 않고, 근거와 방향을 먼저 확인한 뒤 확장한다.

## 진행 순서

1. **요구·청중·결정** — 누가 보고 무엇을 결정하는지, 형식·분량·필수 요소를 정한다.
2. **내용 근거** — 슬라이드별 주장과 근거 수치·출처를 먼저 표로 만든다. 출처 없는 수치는 넣지 않는다.
3. **3장 샘플** — 표지·본문·표/차트가 섞인 3장을 만들어 방향을 확인한다. 이 단계를 통과하기 전에 전체를 만들지 않는다.
4. **전체 생성** — 샘플의 톤·여백·서체를 유지한다.
5. **재검증** — 생성한 파일을 다시 열거나 렌더해 확인한다.

## 작성 규칙

- 제목에 판단을 담는다. "배경", "현황" 같은 항목명만 쓰지 않는다.
- 슬라이드 하나에 핵심 메시지 하나.
- 표·차트는 편집 가능한 네이티브 객체로 만든다. 이미지로 대체하지 않는다.
- 원본 템플릿·마스터를 바꾸지 않는다. 지정 양식이 우선이다.
- 화면 발표용과 배포용은 텍스트 밀도를 다르게 한다.

## 검증

| 대상 | 확인 |
|---|---|
| 레이아웃 | 페이지 넘침, 겹침, 잘림, 줄바꿈, 대비 |
| 내용 | 제목만 읽어도 메시지가 전달되는가, 수치와 출처가 맞는가 |
| 편집성 | 표·차트·텍스트가 네이티브로 남아 있는가 |
| 파일 | 슬라이드 수, 변환·렌더 실패 여부, 깨진 글꼴 |

- 정적 검사, 렌더 확인, 실제 상호작용을 구분해 적는다.
- 스크린샷은 캡처한 상태의 증거일 뿐 상호작용이나 편집 가능성의 증거가 아니다.
- 렌더러·글꼴·템플릿이 없어 확인하지 못했으면 미검증으로 보고하고 통과로 쓰지 않는다.

## 보고

산출물과 형식, 실제로 수행한 검사와 결과, 누락·부분 실패, 미검증 항목을 적는다. 근거 없는 품질 점수는 쓰지 않는다.
