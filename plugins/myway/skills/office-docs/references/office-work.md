# 오피스 산출물 작업 규칙

문서·표·발표자료를 만들거나 고칠 때 공통으로 지키는 규칙이다.

## 원본 보존

- 원본을 덮어쓰지 않는다. 작업 사본을 만들고 경로·이름 규칙을 지킨다.
- 기존 양식을 받으면 서식·구조를 유지하고, 바꾼 내용과 이유를 기록한다.
- 되돌릴 수 없는 변환(포맷 변경·병합)은 사본에서 먼저 확인한다.

## 수치와 표

- 모든 수치에 출처와 기준일을 붙인다. 단위를 생략하지 않는다.
- 계산 결과는 수식·합계를 다시 검산한다. 수식 오류가 남으면 완료로 보지 않는다.
- 표의 열·행을 바꾸면 인용·참조도 함께 고친다.

## 서식과 접근성

- 스타일을 상속해 일관성을 유지한다. 직접 서식을 남발하지 않는다.
- 이미지에는 의미를 담은 대체 텍스트를 넣는다. 색만으로 정보를 구분하지 않는다.
- 화면과 인쇄(또는 PDF) 양쪽에서 잘림·겹침을 확인한다.

## 시각 검증과 보고

- 파일 구조·텍스트·수식 검사는 화면에 표시되는 모양을 보증하지 않는다. 렌더된 각 페이지·슬라이드와 필요한 시트의 인쇄 영역을 살펴 잘림, 겹침, 글꼴 대체와 가독성을 확인한다. 화면과 인쇄/PDF가 모두 요구되면 각각 확인한다.
- 렌더 이미지가 증명하는 것은 해당 파일 버전과 렌더러·글꼴 환경에서 확인한 범위의 외관뿐이다. 편집 가능성, 수식의 정확성, 링크·상호작용은 별도로 검사한다.
- 검사한 파일, 도구·환경, 페이지나 시트 범위와 발견 사항을 보고한다. 렌더 실패, 도구·글꼴 부재 또는 일부만 확인한 경우에는 빠진 범위와 이유, 영향 및 필요한 후속 확인을 `미검증`으로 적고 시각 검증 전체 통과를 주장하지 않는다.

## 파일과 정보

- 파일명에 버전·날짜를 넣고, 같은 이름의 최종본을 덮어쓰지 않는다.
- 개인정보·자격증명·내부 주소를 본문·메타데이터·숨김 영역에 넣지 않는다.
- 배포 전 메타데이터(작성자·회사·경로)를 확인한다.

## 완료 전 점검

- [ ] 플레이스홀더·임시 문구가 남아 있지 않다
- [ ] 수치·합계·수식이 검산됐다
- [ ] 출처·단위·기준일이 표에 있다
- [ ] 시각 검증(잘림·겹침·깨짐)을 마쳤다
- [ ] 개인정보·비밀값이 없다
- [ ] 실행하지 않은 검증을 완료로 쓰지 않았다
