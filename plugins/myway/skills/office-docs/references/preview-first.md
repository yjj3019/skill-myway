# 긴 산출물은 미리보기 후 작성

새 Office 파일, 장문 매뉴얼, 긴 보고서·기고처럼 작성·생성 비용이 큰 산출물은 완성본 전에 한 번만 사용자 확인을 받는다.

- 조사와 자료 확인은 먼저 진행해도 된다. 본문 집필이나 파일 제작 전에 채팅으로 짧은 HTML 개요를 보여주고, 한 번 승인받는다.
- 미리보기에는 제목과 개요, 슬라이드/시트 구성, 핵심 결론, 미확정 입력만 담는다. 표가 필요하면 헤더와 가상 대표 행 하나만 보인다. 본문 문안·모든 행·인용 자료를 복제하지 않는다.
- HTML 조각은 `<section>`, `<h2>`, `<p>`, `<ul>`, `<li>`, `<table>` 등 필요한 구조만 사용한다. CSS·스크립트·장식은 넣지 않고, HTML 파일은 저장하지 않는다.
- “이 구성으로 최종본을 작성할까요?”처럼 결과물에 맞춰 한 번 묻고 명시적 승인을 기다린다. 확인 전에는 전체 본문 작성, DOCX/PPTX/XLSX/PDF 생성, 정적 목차 빌드, 변환·렌더 임시물 생성을 보류한다.
- 승인 뒤에는 미리보기 내용을 재사용해 생성한다. 완성 파일의 전체 내용을 응답에 다시 출력하지 말고 파일 링크와 검증 결과·미확인 범위만 짧게 알린다.

예외:

- 사용자가 “미리보기 생략”, “완성 파일을 지금 생성”처럼 현재 요청에서 생성 의사를 분명히 밝혔거나, 요청에 구체적 유형·범위·구성이 모두 있어 추가 선택이 필요하지 않으면 미리보기를 생략할 수 있다. 포맷만 지정한 경우는 충분하지 않다.
- 읽기·검토만 하는 요청, 대화로 답하는 요청, 기존 파일의 작은 국소 수정, 이미 승인한 동일 구성의 후속 생성은 확인을 반복하지 않는다.
- 사용자 피드백으로 핵심 내용, 분량, 구성이나 자료 범위가 크게 바뀌면 바뀐 부분만 다시 보여주고 한 번 더 확인한다.
