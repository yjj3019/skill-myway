# 간단 미리보기 후 파일 만들기

새 문서·발표자료·대형 통합문서처럼 생성·렌더링 비용이 큰 파일은 최종 산출 전에 한 번만 사용자 확인을 받는다.

- 원자료를 읽고 핵심 내용·구성을 정한 뒤, 파일이나 변환·렌더 중간물을 만들기 전에 채팅에 짧은 HTML 미리보기를 보여준다.
- 미리보기는 제목, 목차·슬라이드·시트 구조, 핵심 결론·수치, 빠진 입력·가정만 담는다. 표는 대표 행 하나면 충분하다. 전체 본문, 모든 슬라이드 문안, 모든 행을 복제하지 않는다.
- HTML 조각은 `<section>`, `<h2>`, `<p>`, `<ul>`, `<li>`, `<table>` 등 필요한 구조만 사용한다. CSS·스크립트·장식은 넣지 않고, HTML 파일은 저장하지 않는다.
- “이 구성으로 파일을 만들까요?”라고 한 번 묻고 명시적 승인을 기다린다. 확인 전에는 DOCX/PPTX/XLSX/PDF, 정적 목차 빌드, 변환·렌더 임시물을 만들지 않는다.
- 승인 뒤에는 미리보기 내용을 재사용해 생성한다. 완성 파일의 전체 내용을 응답에 다시 출력하지 말고 파일 링크와 검증 결과·미확인 범위만 짧게 알린다.

예외:

- 사용자가 “미리보기 생략”, “완성 파일을 지금 생성” 등 현재 요청에서 바로 최종 파일을 만들라고 분명히 한 경우 확인 단계를 건너뛴다. 포맷을 지정한 사실만으로는 생략 승인이 아니다.
- 읽기·검토만 하는 요청, 대화로 답하는 요청, 기존 파일의 작은 국소 수정, 이미 승인한 동일 구성의 후속 생성은 확인을 반복하지 않는다.
- 사용자 피드백으로 핵심 내용, 분량, 구성이나 자료 범위가 크게 바뀌면 바뀐 부분만 다시 보여주고 한 번 더 확인한다.
