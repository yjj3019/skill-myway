# CVE 조사 결과 요약 문서

이 서식은 사용자가 여러 건의 결과를 표나 요약 보고서로 요청한 경우에 쓴다. 다수 CVE를 조사해 달라는 말만으로 이 모드로 바꾸지 않는다. 통합 리포트는 `report-format.md`의 형식을 따른다.

저장 파일명: `CVE_요약_YYYYMMDD_{N}건.md`. `{N}`은 정규화 및 중복 제거가 끝난 ID 수다. claude.ai에서는 `/mnt/user-data/outputs/`에 저장하고 `present_files`로 전달한다. 다른 환경에서는 현재 작업 폴더에 만들고 경로를 알린다.

## 문서 골격

```markdown
# RHEL CVE 조사 요약: {N}개 ({YYYY-MM-DD} 기준)

## 범위
## 전체 건수
## 판정별 결과
## 제품별 패치 확인
## 조사 공백과 주의점
## 확인한 자료
```

첫 입력 수와 고유 식별자 수를 `전체 건수`에 모두 표시한다. 대상 RHEL 버전은 요청자가 지정한 범위로 한정한다. 범위 미지정이면 실제 자료에 나타난 주요 버전만 본다. 자료에서 찾지 못한 버전을 임의로 추가하지 않는다.

## 건별 정리 절차

각 CVE의 제품 상태, 패치 릴리스, EPSS, KEV를 따로 수집한 뒤 아래 분류 중 하나를 정한다. 분류는 개별 제품 근거를 대신하지 않으므로 버전별 상태도 같이 적는다.

1. **업데이트 적용** — 요청 범위에 수정 릴리스가 확인됨.
2. **완화 또는 재검토** — 영향이 기록됐고 수정판이 없거나, 조사가 끝나지 않았거나, 공급자가 수정하지 않기로 한 상태.
3. **지원 종료** — 요청한 제품 흐름이 지원 범위 밖.
4. **비영향** — 대상 버전의 제품 레코드가 명시적으로 비영향을 나타냄.
5. **다른 Red Hat 제품만 확인** — Red Hat 자료에 제품 레코드는 있지만 요청 범위의 RHEL 레코드는 없음.
6. **제품 상태 자료 없음** — CVE 레코드가 있으나 상태와 수정 패키지 정보가 모두 비어 있음.
7. **Red Hat 레코드 미발견** — 검색과 공식 CVE 경로에서 항목을 찾지 못함.
8. **판정 유보** — 접근 실패, 충돌, 또는 근거 부족으로 결론을 정할 수 없음.

어떤 제품에서는 업데이트가 있고 다른 제품에는 아직 영향 상태가 남을 수 있다. 대표 분류는 가장 적극적인 조치가 필요한 쪽으로 두고, 나머지 버전별 결과를 숨기지 않는다.

## 전체 건수 확인

상단에는 접수된 ID 수와 고유 ID 수를 적고, 집계 표는 요약 범위를 투명하게 보여준다. 최소한 다음 숫자를 넣는다: Red Hat 자료 확인 수, RHEL 상태 확인 수, 업데이트 적용, 완화/재검토, 지원 종료, 비영향, 다른 제품만 확인, 제품 상태 자료 없음, 레코드 미발견, 판정 유보.

내부 검산 기준:

- 네 가지 RHEL 조치 결과(업데이트, 완화/재검토, 지원 종료, 비영향)의 합은 상태를 찾은 CVE 수와 같아야 한다.
- RHEL 상태가 없는 확인 CVE는 다른 제품 또는 제품 상태 자료 없음으로 각각 분류한다.
- Red Hat 레코드 미발견과 판정 유보까지 더한 값이 고유 CVE 수와 맞아야 한다.

식이 맞지 않으면 표를 제출하지 말고 입력 중복과 자료 누락을 다시 확인한다.

## 판정별 결과

하나의 대형 CVE 표로 모든 상태를 나열하지 않는다. 판정명별 작은 표를 나눠 만든다. 각 CVE는 정확히 한 곳에만 나타나야 한다.

요약 표는 다음 필드를 담는다: `CVE ID | 컴포넌트 | 한국어 핵심 결과 | 심각도 | CVSS | EPSS | KEV | 대상 RHEL 상태`.

- 판정 그룹 안에서는 Red Hat CVSS 값이 높은 순, 이후 CVE ID 순으로 정리한다.
- 설명은 출처에 근거한 한 문장으로 제한한다.
- 심각도는 Red Hat이 제공한 영문 label을 보존한다.
- CVSS는 점수·버전·평가 주체가 모두 확인된 경우만 확정 표기한다. 버전 누락은 `버전 확인 안 됨`, 값 누락은 `자료 없음`, 조회 실패는 `미확인`으로 구분한다.
- EPSS 점수와 날짜를 함께 적는다. 점수 없음과 네트워크 실패는 다르게 표시한다.
- KEV 상태는 `등재`, `미등재`, `확인 불가`로 쓴다.
- 제품 상태가 여러 개인 경우 메이저 버전과 스트림을 나눠 보인다. 명시적 제품 레코드가 없는 버전은 `미확인`으로 둔다.

## 제품별 패치 확인

업데이트 적용 또는 완화/재검토 그룹에 해당하는 CVE만 제품·스트림별 표로 정리한다.

표 열: `CVE ID | Red Hat 제품·스트림 | 컴포넌트 | 원문 상태 | RHSA | 수정 패키지와 아키텍처 | 발행일`.

미수정 또는 조사 중인 상태에 RHSA·버전·날짜를 만들지 않는다. errata 본문을 일부만 확인했으면 표 비고에 검토 범위를 적는다. 대상 건이 없으면 `해당 없음`이라고 명시한다.

## 조사 공백과 주의점

JSON/XML 결과 충돌, 지원 종료만 확인된 제품, 다른 Red Hat 제품에 한정된 레코드, 미발견 레코드, 실패한 endpoint, 대체 자료원, 상세 조사가 줄어든 공지는 각각 짧게 기록한다. 접근 실패를 비영향 판정으로 바꾸지 않는다.

특이점이 없다면 `추가 확인 사항 없음`이라고 적는다.

## 확인한 자료

성공적으로 읽은 주소만 적는다. CVE별 자료와 공통 카탈로그를 구분하고, 대체 출처에는 제공자와 자료의 날짜 또는 수집일을 붙인다. 열지 못한 주소는 출처 목록에 넣지 않고 `조사 공백과 주의점`에 실패로 기재한다.

## 표기

HTML·이모지·정렬용 Markdown 표식은 쓰지 않는다. CVSS 출처 간 점수가 다르면 차이를 함께 적는다. epoch 제거가 고객 표시 형식상 필요하면 EVR 비교 이후 표기만 조정한다. 문장은 짧게 쓰고, 출처에 없는 숫자나 제품명을 덧붙이지 않는다.
