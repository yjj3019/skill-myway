# 조사 자료 수집 안내

이 문서는 실제 조사에서 확인할 자료의 종류와 실패 처리 기준을 정한다. 각 출처에서 받은 데이터는 별도 근거로 다룬다. 인터넷 조회 실패를 제품 상태로 바꾸거나, 비어 있는 응답을 임의의 값으로 채우지 않는다.

## 조사 흐름

1. 입력이 RHSB라면 공지에서 CVE와 연관 공지를 식별한다. CVE가 입력이면 연결된 RHSB가 있는지 살핀다.
2. 단일 CVE에서는 Red Hat 취약점 안내 페이지에서 설명, CVSS, 공개 시점, 대응 안내를 확인한다.
3. 제품별 상태 판단은 Hydra 레코드에서 한다. 수정 공지가 있으면 해당 errata에서 날짜와 패키지를 확인한다.
4. 점수, 악용 카탈로그 등재 여부, CVE 설명은 각 출처의 독립된 주장으로 기록한다.
5. 결과 문서에는 성공적으로 확인한 주소만 나열한다. 실패와 확인 범위 제한은 별도로 설명한다.

기술적 접근성만 확인하려는 요청은 본 조회와 분리한다. 같은 endpoint를 단순히 도구만 바꾸어 반복 호출하지 않는다. 응답 상태가 성공이 아니면 본문을 정상 자료로 파싱하지 않는다.

## 웹 도구 제약

어떤 환경에서는 이전 검색 결과에 나온 주소만 열 수 있다. 이 경우 먼저 CVE 또는 RHSA 식별자로 검색해 공식 페이지 링크를 얻은 후 해당 링크를 연다. 검색이나 브라우저 기능이 API 주소를 열지 못하면 그 제약을 명시하고 허용된 대체 출처가 있는지 확인한다. 자료를 못 읽었으면 해당 근거를 `미확인`으로 둔다.

## HTTP 응답 분류

| 관측 내용 | 해석 및 다음 동작 |
|---|---|
| 200이며 응답 구조를 읽을 수 있음 | 원문을 조사 자료로 저장하고 필드를 검토 |
| 404 | 요청한 경로에서 자료를 찾지 못함. 다른 제품이 영향 없다는 증거가 아님 |
| 403, DNS/연결 실패, 시간 초과 | 접근할 수 없어 판정을 보류 |
| 200이지만 예상 형식이 아님 | 형식 오류 또는 상위 서비스 안내 응답인지 확인 |
| JS 안내 페이지만 관측 | 이 본문만으로 제품 상태를 정하지 않음 |

## Red Hat 보안 페이지

CVE 페이지는 설명, 보안 의견, CVSS, CWE, 공개 날짜, 완화 설명, 연결된 공지의 존재를 확인하는 출처다. 동적으로 채워지는 제품 표가 페이지 출력에서 보이지 않더라도 제품 영향이 없다는 뜻은 아니다.

완화 정보에서는 실제로 실행할 수 있는 조치와 일반 안내 문장을 구별한다. 명령은 공급자 문서나 별도 시험에서 확인한 경우만 제시한다. 페이지를 읽지 못했다면 내용을 기억이나 유사 사례로 채우지 않는다.

## Hydra 응답

CVE endpoint는 JSON과 XML 표현을 제공한다.

```text
https://access.redhat.com/hydra/rest/securitydata/cve/{CVE-ID}.json
https://access.redhat.com/hydra/rest/securitydata/cve/{CVE-ID}.xml
```

응답을 읽을 때 제품 상태를 담은 `package_state`와 패치 발행 자료인 `affected_release`를 따로 취급한다. 한 목록에 나오지 않는다고 다른 목록의 사실이 지워지는 것은 아니다. 제품명, 스트림, 상태, 패키지, RHSA, 발행일을 원자료에서 확인해 기록한다.

사용자 대상 제품의 결론을 정하는 값이 JSON과 XML에서 다르면 양쪽을 보존하고 충돌로 보고한다. 어떤 형식이 권위 있는지 확정할 수 없으면 내부 기준 선택을 밝히고 미해결 상태를 함께 표시한다.

## 제품 공지와 패키지 버전

패치 레코드가 있을 때 `https://access.redhat.com/errata/{RHSA-ID}`에서 공지 날짜와 대상 제품, 패키지 버전을 찾는다. 광범위한 패키지 공지를 전수 대조하지 못한 경우는 확인 범위를 줄여 적는다. 라이브 패치 공지와 일반 패키지 공지는 별도 항목이다.

아키텍처별 정확한 패키지 문자열이 필요하면 Red Hat의 보안 권고 JSON 자료를 확인한다. 버전 비교 전 원본 EVR을 보존하고 RPM 규칙으로 비교한다. 도구가 없을 때는 단순 정렬 대신 판단을 보류한다.

## EPSS 데이터

`python3 scripts/epss_kev.py CVE-2099-00001`은 First.org의 공개 EPSS API에서 요청 ID를 찾아 점수와 백분위를 읽는다. 특정 ID가 응답에 없거나 사용할 수 없는 행이면 해당 ID에 대해서만 공개 CSV 보조 자료를 조회한다. 두 경로 모두 실패한 경우 각각의 오류 코드가 출력에 남는다.

수동 웹 조회에서는 다음 API 주소를 사용할 수 있다.

```text
https://api.first.org/data/v1/epss?cve={CVE-ID}
https://raw.githubusercontent.com/lucacapacci/epss/main/data_single/{YYYY}/{CVE-ID}.csv
```

요청한 식별자와 응답의 CVE가 같은지 확인한다. 점수, 백분위, 응답 날짜를 함께 기록하며 유효한 레코드가 없다는 이유로 0점 처리하지 않는다.

## CISA KEV 자료

스크립트는 CISA가 직접 게시한 JSON catalog를 한 번 읽고 각 입력 CVE를 대조한다.

```text
https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json
```

카탈로그 자체를 읽지 못했거나 구조가 예상과 다르면 등재 여부는 `unknown`이다. 읽기에 성공한 카탈로그에 항목이 없을 때만 미등재로 표현한다. 등재 자료가 있으면 등록일, 기한, 이름 등 확인 가능한 필드와 카탈로그 개정일을 보존한다.

KEV 기록은 알려진 악용 목록에 존재한다는 근거다. 그것만으로 Red Hat 제품이 영향을 받는다고 결론내리지 않는다. KEV 항목의 공급자·제품이 다른 경우에는 Red Hat 패키지와 구현체가 연결되는지 확인한다.

## 대체 출처와 기록

원문을 열 수 없을 때 공개 CVE 레코드, 공급자 보안 권고, OSV 같은 다른 출처를 활용할 수 있다. 사용한 출처의 이름과 게시/조회 시점을 밝히고 공급자 원문에서 확인하지 못한 부분을 구분한다. 출처의 형식이 JSON이라는 이유로 내용이 같다고 가정하지 않는다.

참고문서에는 실제 조회한 성공 URL만 기재한다. 차단·오류·미완료 범위는 결과 요약에 남기며, 확인되지 않은 endpoint를 열어 본 자료처럼 적지 않는다.
