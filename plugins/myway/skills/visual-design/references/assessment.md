# 시각 검토 기준 선택

실제 결과를 볼 수 있을 때만 평가한다. 매체·청중·목표와 검토 대상 버전, 캡처 범위·크기, 렌더러와 확인하지 못한 상태를 기록한다. 주관적 선호와 사실 오류를 구분한다.

## 화면별 측정 예시

너비 360 CSS px에서 긴 제목이 잘리는지 확인할 때는 렌더한 화면과 제목 위치, 잘린 제목 수를 함께 기록한다. 페이지가 열리지 않아 세지 못했다면 그 사유를 남긴다. 대비를 기록할 때는 검사한 텍스트·배경 조합과 대비비를 적는다. 수치의 판정 기준은 매체와 요청에 맞춰 정한다.

## 선택형 배점 예시

사용자가 점수 비교를 요청하고 평가자와 기준을 사전에 정한 경우에만 아래 예시를 사용할 수 있다. 필수 기준이나 보편적 합격점이 아니다.

| 관점 | 최대점 |
| --- | ---: |
| 구도 | 20 |
| 정보 위계 | 15 |
| 색채 | 15 |
| 여백과 정렬 | 15 |
| 독창성 | 15 |
| 전달력 | 15 |
| 렌더 품질 | 5 |

독창성은 요청한 브랜드·관습과 접근성을 깨는 정도로 평가하지 않는다. 점수별 판단 기준, 평가자와 검토 조건을 실행 전에 정하고 실제 관찰 위치를 남긴다. 이미지나 필수 화면이 없으면 해당 항목은 미평가로 두고 임의의 0점이나 만점으로 채우지 않는다.

기술 도식은 노드와 연결의 의미, 화살표 방향, 텍스트 가독성과 겹침을 별도로 확인한다. 필수 내용의 왜곡·잘림은 총점이 높아도 해결해야 한다. 화면 이미지의 점수는 조작 가능성, 스크린리더, 실제 독자의 이해도나 사실 정확성을 보증하지 않는다.

## 예정 화면과 실제 캡처 대조

스킬 폴더에서 `python scripts/check_design_review.py ROOT MANIFEST.json --plan PLAN.json`을 실행한다. 스키마 3은 Python과 Pillow가 필요하다. 계획에는 렌더하기 전의 원본 파일 해시와 이미지의 최종 픽셀 크기를 적는다. CSS 뷰포트와 다를 수 있다. `HASH`는 해당 파일의 실제 SHA-256으로 바꾼다.

```json
{"schema_version":1,"artifacts":{"sample":{"source_sha256":"HASH","surfaces":{"compact.png":[800,600],"wide.png":[1280,720]}}}}
```

관측 파일에는 `schema_version: 3`과 `artifacts` 배열을 넣는다. 각 항목은 `id`, `kind`, `source`(경로·해시), `surfaces` 배열을 가진다. 아래는 화면 한 건의 예다. `source_sha256`과 `render_sha256`은 각각 원본과 캡처의 실제 해시다.

```json
{"index":1,"render":{"path":"compact.png","sha256":"HASH"},"review":{"source_sha256":"HASH","render_sha256":"HASH","status":"NOT VERIFIED","open_critical":0,"open_major":0},"measurements":[{"name":"본문 대비","reason":"배경색 미측정"}]}
```

`plan_coverage`에서 예정·관측 수와 누락·예정 외 화면·크기·원본 불일치를 확인한다. 계획 대조 명령은 범위가 일치하고 선언된 실패가 없으면 종료 코드 0이다. 실제 품질은 별도 판정하며 측정할 수 없던 항목은 계속 미검증으로 남긴다.
