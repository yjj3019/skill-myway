# 결정 기록(ADR)

산출물·시스템의 중요한 선택을 나중에 설명할 수 있게 남긴다. `docs/DECISIONS.md`가 이 저장소 운영 결정이라면, ADR은 개별 프로젝트·산출물의 기술 결정이다.

## 언제 쓰나

- 공개 API·인터페이스·스키마를 바꿀 때
- 구조·의존성·저장소 선택을 바꿀 때
- 운영 정책(배포·백업·권한)을 정할 때
- 같은 설명을 반복하게 될 때

사소한 구현 선택에는 쓰지 않는다.

## 형식

| 항목 | 내용 |
|---|---|
| 제목 | 결정을 한 줄로(예: "세션 저장을 파일에서 DB로") |
| 상태 | 제안 / 채택 / 폐기 / 대체됨(대체 ADR 번호) |
| 날짜 | 결정일 |
| 맥락 | 문제, 제약, 이해관계자 |
| 결정 | 무엇을 하기로 했는가 |
| 대안 | 검토한 선택지와 기각 이유 |
| 결과 | 좋아지는 점, 감수하는 비용·위험 |
| 되돌림 조건 | 어떤 전제가 깨지면 재검토하는가 |
| 참고 | 근거 링크·측정·관련 문서 |

## 작성 규칙

- 결정과 이유를 중심으로 쓴다. 회의 기록·배경 설명을 길게 붙이지 않는다.
- 대안을 최소 하나 적고, 왜 선택하지 않았는지 밝힌다.
- 수치·날짜에는 근거와 기준일을 붙인다.
- 결정을 바꾸면 기존 ADR을 고치지 않고 새 ADR로 대체한다.
- 구현 세부는 코드·설계 문서에 두고, ADR은 "왜"를 남긴다.

## 예시 (가상)

- 제목: 세션 저장을 파일에서 DB로 변경
- 상태: 채택 (2026-01-05)
- 맥락: 인스턴스 2대 이상에서 파일 세션이 공유되지 않음. 로그인 유지 실패 보고 3건.
- 결정: 세션을 DB 테이블에 저장하고 TTL을 둔다.
- 대안: 스티키 세션(장애 시 유지 불가), 외부 캐시(운영 비용 증가).
- 결과: 다중 인스턴스 로그인 유지. DB 쓰기 부하 증가.
- 되돌림 조건: 세션 쓰기가 DB 병목의 20%를 넘으면 외부 캐시 재검토.

예시 값은 모두 가상이다.
