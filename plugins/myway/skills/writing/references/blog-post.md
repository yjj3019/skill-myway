# 블로그 게시글 추가 기준

개인 블로그·기술 블로그에 공개할 글을 쓸 때 `writing` 공통 기준 위에 얹는 점검이다. 매체 게시 규격이 따로 있으면 그 규격이 우선하고, 이 문서는 문장과 공개 점검만 보탠다.

## 1. 공개 전 개인정보 점검

본문, 제목, 이미지 설명(대체 텍스트), 태그, 코드, 메타데이터, 작성 메모 어디에도 넣지 않는다.

- 이름, 연락처, 이메일, 정확한 거주지·직장 위치
- 계정·인증 정보, 결제·금융 정보, 건강 정보
- 미성년자·제3자를 식별할 수 있는 내용, 얼굴, 차량 번호, 기기 일련번호, 주문 번호
- 비밀값(토큰·쿠키·키·비밀번호). 필요한 예시는 `<API_TOKEN>`, `<PRIVATE_VALUE>` 같은 자리표시자로 바꾼다.

원문에 개인정보가 있으면 공개용 출력에서 지우고 작성 메모에도 다시 쓰지 않는다. "개인정보는 생략함" 정도만 남긴다.

기억이나 이전 대화, 계정 프로필에서 개인 사실을 끌어오지 않는다. 이번 요청에서 제공했거나 첨부한 사실만 쓴다. 스크린샷·로그·영수증·문서 메타데이터도 같은 기준으로 확인하고 필요한 부분은 가린다.

## 2. 재료 구분

- 확인된 사실, 직접 겪은 경험, 의견을 나눠 적는다.
- 제공되지 않은 구매·방문·테스트·감정·비용·후원 여부를 만들지 않는다.
- 제품·서비스 후기에는 대가성 여부를 제공된 범위에서 밝힌다.

## 3. 작업 흐름

1. **재료 정리**: 사실·경험·의견을 구분하고 빠진 사실은 질문으로 남긴다. 추측으로 채우지 않는다.
2. **구조 선택**: 글 종류에 맞는 흐름을 고르고 제목과 도입을 정한다. 고정 템플릿을 강요하지 않는다.
3. **문체 정리**: 프로필의 문체로 한 번에 정리한다. "자연스럽게 다듬기"와 "AI 티 줄이기"를 같은 목표로 보고 반복 재작성하지 않는다.
4. **공개 전 점검**: 위 1절, 사실·경험 구분, 모바일 가독성, 명령·버전·설정의 정확성, 끝맺음.

## 4. 구성

- 도입은 실제 계기나 질문으로 시작한다. "안녕하세요, 이번 포스팅은..."은 개인 블로그에서 어울릴 때만 쓴다.
- 문단은 1~3문장을 기본으로 하되 설명이 필요한 곳은 늘려도 된다.
- 소제목·목록·표는 비교나 절차 파악에 도움이 될 때만 쓴다.
- 마지막은 확인된 한계·적용 조건으로 닫는다. 요약 반복이나 격언으로 끝내지 않는다.

## 5. 출력

- 제목과 완성 본문을 먼저 준다.
- 끝맺음은 프로필을 따른다. 개인 블로그 완성 글은 마무리 문장 뒤에 "끝."을 다음 줄에 둘 수 있다.
- 요청받은 경우에만 해시태그·요약·이미지 설명을 붙인다. 제공되지 않은 사진이 있는 것처럼 쓰지 않는다.
- 확인이 필요한 비민감 사실만 구분선 아래 `작성 메모`에 남긴다.
