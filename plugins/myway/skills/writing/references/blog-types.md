# 블로그 글 유형과 변주

같은 문체라도 글 유형과 매체에 따라 구성이 달라진다. 유형을 먼저 고르고, 그 유형의 구조 신호를 따른다.

## 유형 선택

| 유형 | 핵심 독자 질문 | 기본 구조 |
|---|---|---|
| 개념·동향 해설 | 이게 왜 중요한가 | 문제 제기 → 개념 설명 → 사례 → 실무 영향 |
| 실전 가이드 | 어떻게 하는가 | 전제 → 단계별 실행 → 확인 → 주의점 |
| 릴리스 해설 | 무엇이 바뀌었나 | 변경 요약 → 주요 변경 → 영향 → 확인 사항 |
| 비교·벤치마크 | 무엇이 더 나은가 | 기준 → 측정 조건 → 결과 → 해석과 한계 |
| 트러블슈팅 기록 | 무엇이 문제였나 | 증상 → 원인 추적 → 해결 → 재발 방지 |
| 구축·케이스 기록 | 어떻게 만들었나 | 요구 → 설계 → 구현 → 결과 → 배운 점 |
| 소식·브리프 | 무슨 일이 있었나 | 사실 → 맥락 → 의미 → 독자 행동 |
| 제품 사용기 | 써 보니 어떤가 | 계기 → 사양·구성 → 사용 과정 → 장단점 → 맞는 사용자 |

## 제목

- 질문형, 수치·결과형, 부제형, 완결문장형 중 유형과 어울리는 것을 고른다.
- 제목에 근거 없는 최상급을 넣지 않는다. 본문에서 다루지 않는 약속을 제목에 쓰지 않는다.
- 같은 유형의 글을 연속으로 쓸 때 같은 패턴을 반복하지 않는다.

## 섹션명과 톤

- 클로징·참고자료 섹션 이름을 매번 같게 쓰지 않는다. 같은 세션에서 반복하면 인위적으로 읽힌다.
- 톤(1인칭 경험형, 설명형, 실무형)은 글 하나에서 유지한다.
- 1인칭 경험은 제공된 경험에만 쓴다. 경험을 꾸미지 않는다.

## 적용 규칙

- 매체 게시 규격이 있으면 그 규격이 우선이다.
- 유형은 구성의 출발점일 뿐이다. 모든 글을 같은 틀로 자르지 않는다.
- 분량은 유형과 요청 범위를 따른다. 늘리기 위해 배경을 반복하지 않는다.
- 사실·개인정보 기준은 `references/facts-and-privacy.md`를 따른다.
