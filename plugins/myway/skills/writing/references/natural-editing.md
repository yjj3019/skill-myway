# 자연스러운 문체와 사실 보존

문체 편집은 탐지기 회피가 아니라 독자의 이해와 작성자의 의도를 돕는 작업이다. 판정 도구의 결과나 특정 단어만으로 작성 주체를 단정하지 않는다.

1. 독자에게 필요한 결론과 근거를 찾아 반복되는 도입·전환·요약을 문맥에 맞게 줄인다. 필요한 예외와 주의는 남긴다.
2. 추상적 평가를 제공된 사실과 관찰로 구체화한다. 실제 경험, 감정, 인용, 숫자와 사례는 없는 것을 만들지 않는다.
3. 문장 길이와 문단 구조를 내용의 관계에 맞춘다. 일부러 불규칙하게 만들거나 오탈자·구어체를 삽입하지 않는다.
4. 수정 전후의 부정, 조건, 인과관계, 확실성, 인용과 기술 문자열을 대조한다. 직접 인용이나 의도적인 반복은 보존한다.
5. 여러 버전을 비교할 때는 명료성, 원문 충실성, 독자와 매체 적합성을 기준으로 평가한다. 독립 판정 없이 개선 효과나 탐지 회피를 보장하지 않는다.

## 원문과 대조하는 순서

1. 요청된 편집 강도와 독자, 매체, 기존 존댓말·구어체 수준을 확인한다. 이미 목적에 맞으면 고치지 않는다. 격식체나 피동문은 문장 역할에 맞는 경우 유지한다.
2. 수치·단위·날짜·버전, 명령과 옵션, 경로·링크, 이름과 직접 인용을 식별한다. 주체·대상·부정·조건·시제·확실성은 정확한 문자열이 같아도 관계가 바뀔 수 있으므로 별도로 살핀다.
3. 불필요하게 반복된 도입이나 관계가 불명확한 문장을 후보로 표시한다. 표현 하나를 발견했다는 이유로 일괄 치환하지 않는다. 중요한 반복은 정확성을 위해 남긴다.
4. 허용된 범위 안에서 주체와 행위를 분명히 하고, 기존 말투와 필요한 격식을 보존한다. 구체적 사례가 입력에 없으면 새 경험이나 감정을 보태지 않는다.
5. 수정 전후를 대조해 보호 대상의 값과 의미 관계가 유지되는지 확인한다. 원문의 모순을 임의로 해결하지 않는다. 확인할 수 없는 부분은 미확인으로 남기고 필요하면 수정 이유를 설명한다.

원문 대조는 모델의 편집 절차다. 모든 정보를 자동으로 탐지하거나 의미 보존을 보장하는 검사기는 아니다.

## 명시적 문자열 검사 선택지

`skill-myway` 작업공간에 `scripts/check_edit_tokens.py`가 있고 사용자가 파일 검사를 요청한 경우, 원문과 편집본을 UTF-8 텍스트로 준비하고 사용자가 보호하려는 정확한 문자열을 UTF-8 JSON 배열로 별도 제공한다. 예를 들어 `python scripts/check_edit_tokens.py --source <원문파일> --edited <편집파일> --protected <목록파일>`로 실행한다. 경로와 자료는 사용자가 허용한 작업 공간에만 둔다. 도구가 없는 설치 환경에서는 설치를 가정하지 않는다.

도구는 목록 순서별로 원문과 편집본의 대소문자를 구분한 비중첩 출현 횟수만 출력한다. 원문에 없는 문자열이나 중복·빈 목록은 입력 오류다. 종료 코드 0은 지정된 문자열들의 횟수 일치, 1은 횟수 변경, 2는 입력 오류다. 값의 순서·의미·부정·조건·출처·사용자 의도는 검증하지 못한다. `MATCH`는 편집 승인이나 의미 보존 판정이 아니므로 해당 내용을 별도로 확인한다. 실제 문자열이나 본문은 결과에 출력하지 않지만 입력 파일 자체의 보호와 수명은 사용자가 관리한다.
