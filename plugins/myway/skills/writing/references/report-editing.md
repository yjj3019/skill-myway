# 보고서·설명 문장 편집 (근거 보존)

보고서·PR 설명·완료 보고의 문장만 다듬어 달라는 요청에 쓴다. 실행 정책·판정·테스트 결과는 편집 대상이 아니다.

## 절차

1. **독자와 결정 파악.** 누가 읽고 무엇을 판단하는지 정한다. 새 정보와 결론을 앞세우고 반복 배경·근거 없는 칭찬을 줄인다.
2. **주장 인벤토리.** 수치·단위, 이름, 날짜, 인용, 조건, 부정, 불확실성, 인과·순위·동시성 주장, 검증 범위를 목록으로 적는다.
3. **문장만 재작성.** 구체적 서술과 익숙한 용어를 쓴다. 정보를 담은 대비·경고·목록은 유지한다.
4. **양방향 대조.** 남긴 주장에 근거가 있는가, 원문의 핵심 주장이 빠지지 않았는가를 모두 확인한다.
   - 테스트 skip·실패·`NOT VERIFIED`·fixture/실서비스 구분은 의미를 바꾸지 않는다.
   - 도구의 거부를 격리 증명으로, fixture 성공을 실서비스 인증으로 바꾸지 않는다.
5. **불확실하면 원문 유지.** 동등성 판단이 어려우면 원문을 두고 질문으로 남긴다.

## 보호 구간

코드 블록, 인라인 코드, 명령, 경로, URL·링크 대상, YAML 메타데이터, 스키마, 결과 표, 인용, 증거 식별자는 바이트 그대로 둔다. 고칠 필요가 있으면 조용히 바꾸지 말고 따로 제안한다.

## 한국어

- 같은 대상에는 같은 용어를 쓴다.
- "혁신적인", "획기적인", "이를 통해" 같은 표현은 의미가 없을 때만 줄인다. 금지어 목록이 아니다.
- "검증하지 않음", 조건·한계·안전 경고는 결과를 규정하면 유지한다.
- 영어 문장부호·어휘 규칙을 한국어 규칙으로 일반화하지 않는다.

## 출력

- 요청이 편집만이면 최종 문장만 준다.
- 검토 요청이면 주요 변경과 미해결 주장을 짧게 덧붙인다. 초안·체크리스트는 요청받았을 때만 보여 준다.
